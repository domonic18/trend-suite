# 01 trend-suite 整体架构设计

定位：本目录为**架构文档总入口**——先看本文建立全局认知，再按 §五 索引进入各域架构与实现方案。

## 一、系统概述

trend-suite 是趋势交易录播课程的结构化学习平台：把约 69 集、10 卷、≈35 小时课程，加工成**可问、可查、可溯源、可互动**的图文课程与课件。

三块业务面与两条生产线：

| 面 | 使用者 | 形态 | 承载 |
|---|---|---|---|
| 生产工作台 | 教师（`producer`） | 浏览器 Web（云端提供） | 素材入库 → 方案门禁 → 逐节生产 → 教材/课件 → 交接 |
| 伴学客户端 | 学员（`student`） | DSH 框架 + trend-coach 插件 | 体系浏览 → 富媒体课程页 → 带引用问答 → 片段回看 |
| 管理台 / 门户 | 运营（`operator`）、管理员（`admin`）、访客 | 浏览器 Web（云端提供） | 签批发布、模型配置、用量、账号；注册下载、定价、FAQ |

两条交接线：生产线在「**签批 → 发布**」处交给运营；消费线在「**发布内容 → 学员可见**」处开启。

## 二、技术选型

选型纪律：**先看已验证实现**（已跑通过的组合优先于个人偏好），**选型必须写明替换策略**，否则将来调整成本不可估。

### 2.1 运行时与工程

| 项 | 选型 | 备选 | 理由 | 替换策略 |
|---|---|---|---|---|
| 语言/运行时 | Node ≥22 | Bun / Deno | 已在同类实现中验证；DSH 插件生态要求 Node | 不换（插件宿主约束） |
| 包管理 | pnpm workspaces | npm / yarn | 单锁文件、workspace 协议严格、避免幽灵依赖 | 不换 |
| 任务编排 | Turborepo | nx / 自研脚本 | 轻量、按依赖拓扑缓存、配置面小 | 不换 |
| 语言 | TypeScript | JavaScript | 契约可与 zod 同源，端间类型一致 | 不换 |
| 测试 | node:test（原生 runner） | vitest / jest | 零额外依赖，行为基线数字易统计 | 可换，需同步基线口径 |

### 2.2 云端服务

| 项 | 选型 | 备选 | 理由 | 替换策略 |
|---|---|---|---|---|
| Web / 全栈框架 | **Next.js（App Router，React 19）** | Remix / React Router v7 / Nest+Vite SPA | Node 生态 React 全栈框架事实标准：门户 SSG/ISR 原生、管理台与工作台 RSC/CSR、API 用 Route Handlers（Node runtime，SSE 流式与请求体流式自托管无限制）；与 assistant-ui 生态兼容 | 框架层锁定（版本随 React 生态升级）；**领域模块不依赖 Next API**（路由层薄，可再换） |
| 数据库 | PostgreSQL 16 | MySQL | pgvector 支撑向量检索；事务与 JSONB 支撑半结构化产物 | **不换**（检索依赖向量扩展） |
| 向量检索 | pgvector | 独立向量库 | 数据量级（69 集课程）单库够用，少一套运维与一致性 | 数据量超阈值再拆；接口边界已在 [03 数据存储设计](03数据存储设计.md) 固定 |
| 任务队列 | DB 任务表 + worker 轮询（`FOR UPDATE SKIP LOCKED`） | BullMQ / Redis | 无额外中间件；checkpoint 与产物同库，崩溃恢复不依赖本地状态 | 可换队列，但**checkpoint 语义必须留在 DB** |
| 对象存储 | **腾讯云 COS**（生产；S3 兼容接口 + SigV4 预签名，同地域内网免流量费；桶私有读） | 裸本地磁盘 / 自建 minio | 语料 75–140GB 远超单机磁盘；直传与播放签名天然走预签名 | MediaStore 接口抽象，实现可换（本地 FS 仅供开发测试） |
| UI 组件 | React 19 + AntD（管理台/门户）+ assistant-ui（对话） | — | 渲染组件包（课件）跨端复用（React 是硬约束） | 组件库可换，React 不换 |
| 门户渲染 | **Next.js SSG + ISR**（按路由 `revalidate`；多实例需共享 cache handler，当前单实例） | 自研预渲染脚本（已弃） | SEO 与首屏原生支持，取代自研 prerender 管线 | 不换 |

### 2.3 学员端与内容素材

| 项 | 选型 | 理由 | 替换策略 |
|---|---|---|---|
| 宿主 | DeepSeek Harness（web 应用面） | 问答是真对话场景，harness 天然适配 | 不换（换则重开选型） |
| 插件形态 | npm tarball（Host 半 Node + Browser 半 React） | 复用 harness 的会话/凭据/右栏/模型通道 | 不换 |
| 推理 | 云端平台模型 | 零配置 + 合规责任上移 | 不换 |
| 检索 | 云端混合检索（词法 + 向量） | 语料在云端，端侧无索引 | 不换 |
| 播放 | HLS（单码率 6s 分片）+ hls.js + HTTP Range | 免预切片存储；seek 达标依赖 Range | 不换 |
| 教材正文 | Markdown + 容器块 DSL | 可版本化、可服务端校验、可确定性渲染 | DSL 版本只增不减 |
| 课件形态 | **spec + 断言证明**（模型不写代码） | 教学正确性可程序证明 | 白名单扩展需冻结 spec 版本 |
| 图表数值 | 确定性生成器（`generator+seed+bars`） | 可重放、跨端一致、可证明断言 | 生成器白名单化 |
| 案例股行情 | 腾讯前复权源（周期原生 1d/1w） | 单源无备用，口径单一避免冲突 | 换源需重做口径声明与回归 |
| 转码/抽帧 | ffmpeg（固定参数模板） | 参数已跑通 | 换 ffmpeg 需重跑参数回归 |
| ASR | 平台预置 ASR（云端调用） | 教师/学员零密钥 | 换供应商需重验时间戳精度与分段质量 |

### 2.4 契约、质量与版本锁定

| 项 | 选型 | 理由 |
|---|---|---|
| 契约 | zod（`@trend-suite/contracts` 单一真相源）+ 人读 openapi | 校验与类型同源；契约先行门禁 |
| 单一版本 | 全仓 `overrides` 锁 zod 版本 | 防插件生态双实例类型冲突 |
| 校验分层 | 三层：schema → 语义（断言证明/引用/术语）→ 教学质量（rubric） | 失败分类决定回灌还是人工待办 |
| 质量基线 | 行为基线数字（各包测试数）进 README | 改契约前后必须全绿 |
| dsh 宿主 | `engines.dsh` 门禁 `>=0.2.1-rc.5 <0.3.0`；peer 精确同版 | 范围写法会解析到旧依赖链 404 |
| 插件包名 | 发布后不可改（插件 ID 依赖 package.json name） | 改名即断装 |

**契约包必须提供的三件事**（已在同类实现中验证）：

1. **错误语义可定位**：schema 校验失败返回**首个问题**（`firstIssue`）而非错误数组，前端据此高亮第一个出错字段；错误汇聚（`errors-sink`）保证同一次请求的错误只落一处、不重复抛。
2. **人读与机器双向锚定**：openapi.yaml 与 zod 同批变更，由契约测试做**路由级双向锚定**（openapi 有的路由实现必须存在且行为一致；实现有的路由必须在 openapi 出现）。
3. **ID 与枚举形状统一**：`ids.ts` 统一 ID 前缀与形状（`ch_`/`kp_`/`seg-`/`fig_`/`cand_`…），`enums.ts` 统一状态与类型枚举——跨端引用同一 ID 不会因形状不一致而失配。

**CI 门禁**：类型检查 → 单元测试 → 契约测试（对 staging 或本地 compose）→ **OpenAPI 与实现一致性校验**（见 [02 云端服务架构](02云端服务架构.md) §17）。

**工程纪律**：测试库守卫——`TEST_DATABASE_URL` 与 `DATABASE_URL` 必须指向不同库，同库即拦截（测试会清空目标库）；zod 等易双实例依赖全仓锁定单版本；改契约前后行为基线数字必须全绿。

**明确不做的选择**：独立向量数据库、Redis/MQ 中间件、微服务拆分、生成式代码（h5-page / LLM 生成可执行课件）、端侧推理、前端微前端。

### 端职责边界

| 端 | 负责 | 不负责 |
|---|---|---|
| 生产工作台（云端 Web） | 素材入库与骨架（门禁①）、逐节生产看板（三个决策点）、教材轻量编辑、交接 | 签批与发布（运营动作）、模型密钥 |
| 学员插件（coach） | 问答与引用回跳、体系页/课程页渲染、签名播放、即时提问（文字/图片/语音）、本地进度 | 内容存储、检索、鉴权、推理（均在云端） |
| 云端 | 账号与角色、设备码授权、内容存储与混合检索、视频→课程管线、生产编排 worker、发布门禁、签名媒体、额度账本与充值、门户与管理台、AI 计量 | 未经审核的生成内容出口；密钥明文出口 |

角色分权铁律：**producer 只写草稿**（签批/发布/课程状态限 operator/admin）；学员不可进管理台；生成内容一律人工审核显式发布。

## 四、项目目录结构与模块边界

### 4.1 目标目录树（基线）

```text
trend-suite/
├── docs/                    # 全部项目文档（唯一位置）
│   ├── requirement/         #   需求：主题需求.md（每主题一份）
│   ├── arch/                #   架构：本目录（总览 → 各域架构 → 实现方案）
│   ├── prototype/           #   原型：静态 HTML + assets 共享底座
│   ├── flow/                #   端到端流程图
│   └── standard/             #   团队规范
├── apps/
│   ├── cloud/               # 云端：Next.js + PG + 管理台/门户 + 生产 worker + 媒体管线
│   │   ├── src/             #   源码唯一根：src/app 路由 · src/server 领域与 agents · src/features 浏览器侧（4.3；完整树见 02 §2.1）
│   │   ├── public/  skills/ #   静态资产（Next.js 约定在应用根）· deepagents 技能包（SKILL.md，只读挂载）
│   │   ├── db/              #   数据库之家（migrations / initdb / seed）
│   │   ├── deploy/  cicd/   #   镜像与反代 / 发布与监控
│   │   └── compose×3 + .env.example
│   └── coach/               # 学员端 DSH 插件（host/client/shared 三分，§4.4）
├── packages/
│   └── contracts/           # @trend-suite/contracts：zod 契约单一真相源
└── （按需增包，准则见 4.5）
```

**注**：生产编排与工艺包都在 cloud 内，教师端即云端 Web 工作台。

### 4.2 依赖纪律（硬约束）

1. `apps/*` 之间**禁止互相 import**——教师端、学员端的一切协同只经云端接口。
2. `packages/*` **禁止依赖 `apps/*`**——契约与共享资产只向下依赖第三方库。
3. 跨端共享的契约、校验、golden 样本**一律落 packages**；apps 内只留绑定自家错误形状的适配壳。
4. 契约字段与错误码是 wire 契约的一部分：改 `packages/contracts` 前先跑全部测试（行为基线），并与需求/架构文档同批变更（契约先行）。
5. 单一版本原则：zod 等易双实例依赖全仓 overrides 锁定。

### 4.3 apps/cloud：单 `src/` 根 + server / features 成对

- `src/` 是源码唯一根（Next.js `src/app` 官方约定）：`src/app`（路由层）、`src/server`（服务端领域与 agents、worker 入口）、`src/features`（浏览器侧切片）、`src/components`（共享 UI，含 shadcn 与 assistant-ui 注册组件）、`src/lib`、`src/env.ts`、`src/middleware.ts`。完整目录树见 [02 云端服务架构](02云端服务架构.md) §2.1。
- **一个领域两半，同名成对**：`src/server/<域>`（service / repo，真相）+ `src/features/<域>`（ui / api / hooks，浏览器脸）；目录名与 02 §2 模块表一致。
- `src/app/` 只留薄路由层：路由声明、入参校验、调 server 域、按契约映射错误；SQL 与业务规则零落位。
- `src/server/` 以 `server-only` 守卫，禁止进浏览器 bundle；`features/` 一律经 `api.ts` 走 HTTP，不直接 import server 内部。
- **不建横切目录**（不设 `controllers/` `services/`）：横切目录是结构僵化主因——新领域不知进哪个横切层，跨层引用随手发生。
- `db/migrations/NNNN_description.sql` 幂等可回放；数据不变量写在迁移注释。

### 4.4 apps/coach：host / client / shared 三分

| 半 | 运行环境 | 放什么 | 纪律 |
|---|---|---|---|
| `src/host/` | Node | 插件入口、设备码授权、云端客户端与契约校验、工具注册、不可信文本边界 | 入口保持薄；平台注入顺序等硬约束只在 host 处理 |
| `src/client/` | 浏览器（DSH Browser 半） | 面板、播放器、课程页渲染、选中提问、语音采集 | 纯函数尽量拆文件，便于测试 |
| `src/shared/` | 两半 | 共用领域类型与上限常量 | 禁 Node 专属 API（会进 Client bundle） |

### 4.5 packages/ 增包准则（防假想复用）

**只有「已存在 ≥2 个现实消费方」才允许建包**：

| 候选包 | 消费方 | 决定 |
|---|---|---|
| `contracts` | cloud + coach | 已建（唯一例外：契约先行要求它在实现前存在） |
| `widgets`（课件交互组件：K 线/逐根回放/对比滑块…） | coach 课程页 + cloud 成品预览 | **两个消费方成立后建**；spec 与断言契约见 [06 教材呈现与交互课件实现方案](06教材呈现与交互课件实现方案.md) |
| `test-fixtures`（golden 判定样本） | contracts 测试 + cloud 契约测试 | 随首个校验实现落地 |

### 4.6 文档位置与运行期数据

- 全部项目文档在仓库根 `docs/`，按 4.1 分类；`apps/*` 只放代码与运行资产，各自只留 README 指回根文档，并在 `docs/README.md` 登记。
- 运行期数据一律落各应用 `workspace/`（gitignore，不提交）；密钥只走 `.env` 注入与云端加密存储。

### 4.7 结构变更规则

| 变更类型 | 门槛 |
|---|---|
| 领域模块内加文件 | 自由 |
| apps 内新增顶层目录 / packages 增删包 | 先改本文并说明消费方，再动代码 |
| apps/* 增删（端级变更） | 必须先更新本文 §四 的目录结构与边界约定 |
| docs/ 分类调整 | 先改 `docs/README.md` 目录体系表 |

结构基线（违反即视为不合规）：`apps/` 互不依赖 · packages 不依赖 apps · 应用内单层 `src/` · 文档只在根 `docs/` · 运行期数据只在 `workspace/`。
