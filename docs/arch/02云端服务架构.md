## 1. 形态与进程

单服务多域（起步期同进程同库，模块边界预留拆分点）：

```
Next.js 服务进程（App Router，Node runtime，自托管 node server）
├── 页面层（React 19 / RSC）
│   ├── / 门户（公开页：SSG + ISR，按路由 revalidate；注册/登录/设备授权/个人中心）
│   ├── /admin（管理台：会话鉴权 + AntD + 课件预览）
│   └── 工作台（教师生产：方案门禁 / 九步看板 / 轻量编辑 / assistant-ui 对话）
├── API 层（Route Handlers，Node runtime）
│   ├── 入参校验（zod，来自 @trend-suite/contracts）+ 错误映射 + 限流（§15）
│   ├── SSE 流式（agent 运行流 → langgraph-sdk 兼容帧，Web Streams）
│   └── 请求体流式（本地模式直传 PUT：ReadableStream → 临时文件 → 原子 rename）
└── 领域层：accounts / catalog / content / production / pipeline / playback / billing / ai / ops
    （纯 TS 模块，不依赖 Next API——路由层薄，可整体迁离 Next）

Worker 池（同一镜像，独立进程/副本，由 APP_ROLE 区分，不经 Next server）
├── pipeline-worker：上传后处理（转码 / ASR / 关键帧 / 帧轨道）
├── production-worker：Agent 生产编排（九步引擎 + deepagents）
└── quotes-worker：行情缓存回填与日更
```

- 路由前缀（Route Handlers 目录即领域边界）：`/v1/admin/*`（教师/运营/管理）、`/v1/catalog/*`（学员只读内容）、`/v1/auth/*`、`/v1/ops/*`（运营）、`/v1/billing/*`（额度与充值）、`/v1/ai/*`（模型配置与用量）。
- 页面与 API 同源同进程，避免跨域与第二套鉴权。
- 伸缩维度：Next server 按请求量（ISR 多实例需共享 cache handler，当前单实例，见 §15 限流同口径）；pipeline-worker CPU/IO 密集（ffmpeg 子进程限并发）；production-worker 按任务并发（单课并行度另有上限，见 05 文档）。

### 1.1 Next.js 承载边界

| 项 | 约定 |
|---|---|
| 承载内容 | 全部 HTTP：页面（门户/管理台/工作台）+ 全部 `/v1/*` API |
| Runtime | Route Handlers 一律 Node runtime（ffmpeg / pg / deepagents 等仅服务端能力不进 Edge） |
| 流式 | SSE 用 `ReadableStream` 返回（`Cache-Control: no-store`）；请求体流式（直传 PUT）自托管 Node 支持（仅 Serverless 平台受限） |
| 领域隔离 | 领域模块（§2）是**纯 TS**，Route Handler 只做「校验 → 调领域 → 映射响应」，不写业务——框架可替换的保险 |
| 渲染策略 | 门户公开页 SSG/ISR；管理台与工作台 CSR/RSC（`dynamic = 'force-dynamic'` 或按需）；学员端不经页面层 |
| 静态课件渲染组件 | `packages/widgets`（共享包）同时供 Next 页面与学员端插件使用，Next 侧以 client components 嵌入 |

## 2. 领域模块与职责

| 模块 | 职责 | 关键表 | 关键接口族 |
|---|---|---|---|
| `accounts` | 账号、角色、设备码授权、令牌轮换、会话 | users / devices / sessions | `/v1/auth/*` |
| `catalog` | 已发布内容的只读视图：课程树、节详情、目录、进度写入 | courses / sections / progress | `/v1/catalog/*` |
| `content` | 课程内容的权威写面：素材、source units、概念、节教材、图示、课件 spec、案例股 | media_assets / source_units / concepts / sections / figures / widget_specs | `/v1/admin/content/*` |
| `production` | 生产任务状态机、九步引擎、三层校验、回灌与待办、门禁判定、签批与发布 | production_tasks / approvals | `/v1/admin/content/production-*` |
| `pipeline` | 上传落库、转码、ASR、关键帧、帧轨道、HLS 发布 | media_assets / pipeline_jobs / transcript_segments | `/v1/admin/content/media-assets/*` |
| `playback` | 签名播放会话：按节签发 COS 预签名地址（有效期=播放窗），浏览器直连拉流，媒体字节不经云端 | playback_sessions | `/v1/catalog/sections/*/playback` |
| `billing` | 额度账本、扣减、充值、明细 | quota_ledger / recharge_orders | `/v1/billing/*` |
| `ai` | 模型条目（密钥加密）、任务级主备、用量账本、预算 | ai_models / ai_runs / ai_usage_events | `/v1/ai/*` |
| `agents` | 生产 Agent 运行时与四类角色：deepagents 组装、模型通道、确定性工具集、checkpointer（详见 [05 §2.1](05内容生产链路实现方案.md)） | 无自有表——会话由 checkpointer 承载（`thread_id` 关联 `production_tasks`），用量经 `ai` 记账 | 无直接 HTTP；由 `pipeline`（理解）、`content`（综合）、`production`（逐节 / 评审）的任务调用 |
| `ops` | 运营控制台数据：就绪度、发布、账号管理 | 复用上表 | `/v1/ops/*` |

**写面唯一**：所有内容写入只发生在 `content` / `production` / `billing` / `ai` 四个写模块；`catalog` 只读已发布态；`agents` 的产物候选由引擎校验后经 `content` / `production` 落库，**不直写内容表**。学员端永远不直写内容表。

### 2.1 代码目录组织（apps/cloud）

布局采用 Next.js 生态主流约定：单 `src/` 根、`src/app` 路由层、`src/server` 服务端领域、`src/features` 浏览器侧切片、注册组件统一装进 `src/components`。云端应用承载门户 / 管理台 / 教师工作台的全部界面（`src/app` 下的 `page.tsx` 即页面本身）；**DSH 插件只存在于 `apps/coach`（学员端）**。


```text
apps/cloud/
├── public/                       # 静态资产（Next.js 约定：public 固定在应用根）
├── src/                          # 源码唯一根——应用内不存在第二个代码根
│   ├── app/                      # 路由层（App Router）：只做路由声明、页面装配、数据取用
│   │   ├── (portal)/             #   公开门户（SSG + ISR）：主页 · courses 体系 · auth 注册/登录/设备授权 · account 个人中心
│   │   ├── (console)/            #   控制台（Web 会话）：admin/{models,usage,accounts,publish} · workbench/{material,textbook,usage}
│   │   ├── api/v1/               #   全部 API（Route Handlers，Node runtime；目录即路由族边界）
│   │   │   ├── health/route.ts   #     探活（无鉴权，部署冒烟用）
│   │   │   └── auth·admin·catalog·billing·ai·ops/…   # /v1/* 六族 → 各自 server 域
│   │   ├── layout.tsx            #   根布局（主题 / 字体）
│   │   └── globals.css
│   ├── server/                   # 服务端代码（server-only，禁止进浏览器 bundle）
│   │   ├── accounts/ … ops/      #   领域模块——目录名与 §2 模块表同名
│   │   ├── agents/               #   deepagents 运行时与四类角色（[05 §2.1](05内容生产链路实现方案.md)）
│   │   │   ├── agent.ts          #     createDeepAgent 工厂——模型通道/工具/技能/中断/checkpointer 在此装配
│   │   │   ├── roles/            #     comprehension / synthesis / section / review（提示词 + subagents 定义 + 工具白名单）
│   │   │   ├── tools/            #     cloud_* 确定性工具（LangChain tools；{"error"} 语义、幂等回填）
│   │   │   ├── model-channel/    #     BaseChatModel 子类：openai 兼容 + anthropic 双协议（映射见 07 §9.1）、绑定 ai 域、任务级主备、用量记账、预算硬停
│   │   │   ├── checkpointer.ts   #     langgraph-checkpoint-postgres：thread_id = (courseId, sectionId, step)
│   │   │   └── stream.ts         #     astream → langgraph-sdk 兼容 SSE 帧（工作台对话）
│   │   ├── workers.ts            #   worker 进程入口：按 APP_ROLE 分流 pipeline / production / quotes（§1）
│   │   └── lib/                  #   服务端基础设施：db / logger / crypto / http 结果类型 / 时钟（无业务语义）
│   ├── features/                 # 浏览器侧特性切片——与 server 域同名成对，一个领域一个目录
│   │   └── <domain>/             #     ui/（页面组件，供 app/ 取用）· api.ts（本域 fetch 封装与 SSE 消费）· hooks.ts
│   ├── components/               # 跨领域共享 UI
│   │   ├── ui/                   #   基础组件（按钮/表格/表单，AntD 封装；shadcn 注册表安装位）
│   │   └── assistant-ui/         #   开源 React 对话组件库 assistant-ui 的注册组件（工作台 Agent 对话面板：Thread / Message / Composer）
│   ├── lib/                      # 跨端纯函数（同构可用：格式化、常量；无 IO、无 Node 专属 API）
│   ├── env.ts                    # 环境变量校验与出口（zod）——全应用唯一读取点
│   └── middleware.ts             # 会话校验与限流入口（Next middleware）
├── skills/                       # deepagents 技能包（<name>/SKILL.md；由 agents/agent.ts 经 CompositeBackend 只读挂载）
├── db/                           # migrations/（NNNN_description.sql，幂等可回放）· initdb/ · seed/
├── scripts/                      # db/migrate.ts（镜像内 migrate 服务入口）· ops/（backup.sh、load-test.mjs）
├── deploy/                       # Dockerfile（三段式）· caddy/Caddyfile（TLS 终止 + SSE 透传）
├── cicd/                         # deploy.sh（唯一发布入口，§8）· monitoring/
├── docker-compose.yml            # 本地 PG（开发默认）· docker-compose-dev.yml 开发全栈 · docker-compose-prod.yml 上线形态
├── .env.example                  # 配置样例（真实值走环境注入，§9）
├── next.config.ts                # output:'standalone' · ISR 策略（多实例需共享 cache handler，§1.1）
├── components.json               # shadcn/ui 注册表（安装目标 src/components/ui）
├── aui.json                      # assistant-ui 注册表（安装目标 src/components/assistant-ui）
└── tsconfig.json / tsconfig.build.json / package.json
```

**一个领域两半，同名成对**（`server` 是真相，`features` 是它的浏览器脸）：

```text
src/server/content/            # 服务端真相
├── index.ts                   #   唯一出口（service 与类型的 re-export）
├── service.ts                 #   业务规则与用例编排
├── repo.ts                    #   表访问与 SQL（只许出现本域表名）
└── quotes/                    #   子域：行情缓存回填与日更

src/features/content/          # 它的浏览器脸——不 import server 内部，一律走 api.ts
├── ui/                        #   教材渲染、轻量编辑器组件（app/ 的 page 从这里取）
├── api.ts                     #   本域 /v1/admin/content/* 的 fetch 封装与 SSE 消费
└── hooks.ts                   #   浏览器状态（useSection 等）
```

**落位规则**：

1. **`src/app/` 只做装配**：路由声明、参数解析、用 `@trend-suite/contracts` 校验入参、调 `server` 域、按契约映射错误。SQL、业务分支、领域规则零落位。
2. **`src/server/` 不进浏览器 bundle**：每个入口 `import 'server-only'`；`features/` 与 `components/` 只经 `api.ts` 走 HTTP，**不直接 import server 内部**。
3. **领域成对且同名**（`server/<域>` + `features/<域>`），目录名与 §2 模块表一致；新增领域先在 §2 登记。不设横切层（无 `controllers/` `services/`）。
4. **agents 按 deepagents 惯例**：`agent.ts` 工厂 + `roles/` + `tools/`，技能在应用根 `skills/` 只读挂载；产物候选经引擎校验后由 `content` / `production` 落库，agents 不直写内容表。
5. **注册组件用工具装**：shadcn → `src/components/ui`，assistant-ui → `src/components/assistant-ui`；注册组件可改但重装会覆盖，深度定制放 `features/<域>/ui`。
6. **契约不复制**：zod schema、错误码、ID 形状一律来自 `@trend-suite/contracts`。
7. **worker 与 Web 同一模块集**：`src/server/workers.ts` 按 `APP_ROLE` 分流（pipeline / production / quotes），任务逻辑在各域内。
8. **测试与代码同目录**（`service.test.ts`）；环境变量只经 `src/env.ts` 读取；运行期数据只写 `workspace/`（gitignore）。
9. 新增顶层目录须先改本节与 [01 §四 目录结构](01整体架构设计.md)。

## 3. 鉴权与会话

| 主体 | 凭证 | 约束 |
|---|---|---|
| 教师（producer） | Web 会话，token 仅存 `sessionStorage` | 不落 Cookie；无凭据托管面 |
| 运营/管理员 | Web 会话 | 签批/发布/账号/模型配置仅 operator/admin |
| 学员（student） | 设备令牌（Bearer + device id） | 设备不匹配 `403`；令牌自动轮换，只存本机凭据库 |
| 服务间 | 内部签名凭据（直传、播放签名） | HMAC 绑定素材/字节数/摘要/有效期 |

- 分权：producer 只能写 draft；生产端点接受 producer/operator/admin，**发布与审批只接受 operator/admin**。
- 云端文本一律按不可信数据处理（防提示注入）；生成内容出口前过滤。

## 4. 任务编排（DB 队列 + worker）

```
queued ──claim──> running ──success──> succeeded
   │                  ├──retryable failure──> queued（退避 15s/60s/300s + 抖动）
   │                  ├──terminal failure───> failed
   └──cancel──> canceled          └──cancel_requested──> canceled
```

- 认领：`SELECT ... FOR UPDATE SKIP LOCKED` 认领到期任务，认领即 `attempts+1`、写 `locked_*` 与心跳。
- 心跳：默认 10s；启动时与每 30s 回收 `heartbeat_at < now()-120s` 的 running 任务（回 queued 或 failed）。
- 重试：仅网络/上游 429/5xx/ffmpeg 超时等可重试错误；参数或媒体非法为终态失败。`error_code` ≤64 字符，客户端只见稳定码与静态文案。
- 取消：queued 立即 canceled；running 置 `cancel_requested`，worker 在阶段边界检查并中止（ffmpeg `SIGKILL` 子进程并清理工作区）。
- 幂等：已探测时长复用、已提升 HLS 跳过转码、成功 ASR 块复用、产物一次性写；重复调用返回原映射。
- 生产任务按 `(courseId, sectionId, step)` 幂等 upsert；断点续跑的 checkpoint 落 DB（worker 崩溃恢复不依赖本地状态）。

## 5. 生产执行

| 维度 | 约定 |
|---|---|
| 执行位置 | **云端 production worker**（生产端不作为插件运行） |
| 模型 | **云端预置模型**（任务级主备，密钥 AES-GCM） |
| 工艺 | 服务端**版本化工艺配置**（格式待定，见 05 文档） |
| 审批 UI | **工作台审批组件**（方案三动作、评审卡） |
| 产物落库 | worker 直写内容域（仍走同一校验与门禁） |

不变的核心：四角色 Agent、九步固定顺序、三层校验、回灌 ≤3 次、失败进人工待办、发布硬门禁、内容指纹绑定签批（详见 05 文档）。

## 7. 部署形态

| 组件 | 形态 | 说明 |
|---|---|---|
| `apps/cloud` | 容器（Dockerfile，`apps/cloud/deploy/`） | Next.js 自托管（`output: 'standalone'` 产 `server.js`）+ worker（同一镜像，`APP_ROLE` 区分） |
| PostgreSQL | 容器（compose 内） | 起步单实例；数据卷挂 `workspace/` |
| 对象存储 | **腾讯云 COS**（生产，同地域内网；桶私有读）；本地 FS 仅开发测试 | MediaStore 抽象层切换（`MEDIA_STORAGE=cos\|local`）；服务器磁盘只做转码临时工作区 |
| 反代 | caddy（`apps/cloud/deploy/caddy/`） | TLS 终止；SSE 透传需禁用缓冲（`flush_interval -1`） |
| 学员端 | 不部署到服务端 | 一键安装包（DSH 框架 + 插件）分发 |

compose 三件套：`compose.yml`（生产形态）、`compose-dev.yml`（开发）、`docker-compose-prod.yml`（上线形态），均位于 `apps/cloud/`。

### 7.1 同机共存与端口布局

同一台机器上可能同时存在前身系统与 trend-suite，靠**宿主端口**分隔：

| 归属 | HTTP_PORT | HTTPS_PORT | 说明 |
|---|---|---|---|
| trend-suite **staging** | 8080 | 8443 | 预发域名；证书自签（`TLS_ARG=internal`） |
| 前身系统（已让位） | 8081 | **8444** | 停用后回收。**不可用 8443**——那是 trend-suite 预发的端口，两边同端口会互相绑不上 |
| trend-suite **production** | **80** | **443** | 生产域名与原证书，沿用前身系统的原端口 |

**让位顺序**：先把前身系统从 80/443 迁到 8081/8444（只重建它的 caddy 容器，app/db 与数据不动，改端口映射即可回退），再部署 trend-suite production。生产切走后，前身系统的证书无法再续期（ACME 挑战需要 80 端口）——它本就计划停用，可接受。

**云安全组只放行标准端口**（SSH 与 80/443）：预发端口 8080/8443 需另行放行，否则表现为「流水线全绿但浏览器打不开预发地址」（健康检查在服务器内网做，探测不到安全组）。

**门户渲染与运行口径**（Next.js 原生能力取代自研预渲染脚本）：

- 公开页 **SSG + ISR**（按路由 `revalidate`；发布/内容变更可用 on-demand revalidate 精确失效）；`sitemap.xml` / `robots.txt` 由 Next 元数据 API 产出；未知路径落 `not-found` 页并带 `noindex`。
- 动态路由（登录态/个人中心）`force-dynamic` 或依赖会话 Cookie；ISR 仅 Node runtime（默认满足）。
- 公开接口只返回发布清单与聚合计数，不返回正文与内部 ID；门户会话与后台会话**隔离**（`scope=portal`），门户令牌访问后台端点一律拒绝。
- 下载响应强制 `Content-Disposition: attachment`，不暴露可直链的静态路径。
- 多实例部署前必须配共享 `incrementalCacheHandlerPath`（ISR 缓存默认 per-instance）——当前单实例，与 §15 限流同口径。

## 8. 发布流水线（CI/CD）

**环境路由**：push `develop` → **staging**（测试环境，tag `develop-<sha7>`）；push `main` → **production**（tag `main-<sha7>`）。两环境 secret/variable 同名、按 GitHub Environment 隔离。

**统一命名**（两环境同名，按 Environment 隔离取值）：

| 层级 | 名称 |
|---|---|
| 仓库 secret | `TCR_NAMESPACE` / `TCR_USERNAME` / `TCR_PASSWORD` |
| 仓库 variable | `TCR_REGISTRY` / `IMAGE_NAME` |
| environment var | `DEPLOY_HOST` / `DEPLOY_PATH` |
| environment secret | `DEPLOY_SSH_KEY` / `DEPLOY_KNOWN_HOSTS` |

```
PR → check + test（不部署）
push develop/main → check → test（pgvector 同款 + ffmpeg）
   → build（自托管 runner，推 TCR，600s 看门狗 ×3 重试）
   → deploy（SSH 同步部署资产 → cicd/deploy.sh）
        备份 → 迁移先行 → 换容器 → 健康检查 → 失败自动回滚 → 镜像清理
```

唯一部署入口：`apps/cloud/cicd/deploy.sh`（staging 与 production 共用一份，只差 env 文件与 tag 前缀；不得绕过直接改线上容器）。冒烟：`/health`、登录、目录读取、问答额度预检、发布就绪度读取。

### 8.1 compose 侧三条硬约束

改 `docker-compose-prod.yml` 前必须知道——每条都对应一类真实故障：

| 约束 | 不遵守会怎样 |
|---|---|
| **不写死 `name:`**——compose 项目名取部署目录名（两环境目录名不同），靠目录区分环境 | 写死同一个 `name:` 会让两环境抢同一批容器：staging 的 `compose up` 直接替换生产的 app 容器（**生产即中断**），而两边日志都显示「成功」 |
| **`env_file` 用 `${ENV_FILE:?}` 必填**，由 `deploy.sh` `export ENV_FILE` 提供 | 给默认值时 staging 会静默加载生产 env（**生产域名与生产库口令串环境**）；必填 + 缺啥报错是刻意的 |
| **`TLS_ARG` 决定证书来源**：留空 = 公网 ACME；`internal` = caddy 内置 CA 自签 | 预发阶段 80 端口未让出，ACME 的 HTTP-01 挑战走不通 → 证书签不出来、站点不可用 |

### 8.2 首次发布的六个易错点

这六处都会让**首次发布必然失败**，改构建/部署配置时逐条对照：

| 易错点 | 表现 | 正确做法 |
|---|---|---|
| Dockerfile 没拷 `tsconfig.base.json` | `tsc` 报 TS5083，构建阶段失败，根本没有镜像 | 构建阶段 `COPY tsconfig.base.json ./` |
| `CMD` 入口路径与产物不一致 | 产物在 `dist/server/`，容器起来即退出 → 健康检查不过 → 自动回滚 | 入口路径跟随 `tsconfig.build.json` 的 `outDir` |
| compose 写死 `name:` | 两环境抢同一批容器，staging 发布会**替换生产容器** | 不写死，项目名取部署目录名 |
| `env_file` 有默认值 / `ENV_FILE` 没导出 | staging 报 env file not found；或**静默加载生产配置** | `env_file: ${ENV_FILE:?}` + `deploy.sh` `export ENV_FILE` |
| 应用未声明工作区依赖 | pnpm 不装该包 → 运行期 `COPY .../node_modules` 失败 → 镜像构建失败 | 需要契约包就在 `dependencies` 声明 `workspace:*` 并同步 lockfile |
| 迁移脚本静默空跑 | 「迁移先行」门禁形同虚设：schema 没变，线上却以为迁过了 | 迁移未实现时显式告警，不许假装成功 |

### 8.3 接入一台新部署机（一次性）

```bash
# ① 部署目录与属主（pipeline 目录归 node/uid 1000；属主调整放在 pipeline 之后）
for d in <staging-deploy-path> <prod-deploy-path>; do
  ssh <deploy-user>@<deploy-host> "sudo bash -c '
    mkdir -p $d/workspace/{postgres,pipeline,caddy/data,caddy/config,backups}
    chown -R 1000:1000 $d/workspace/pipeline
    chown -R $(id -u):$(id -g) $d $d/workspace'"
done

# ② 环境文件（数据库口令由本机生成，不入库；两环境必须不同）
gen_env() {
  local path="$1" app_env="$2" domain="$3" http_port="$4" https_port="$5" tls_arg="$6"
  local pw; pw="$(openssl rand -hex 16)"        # hex：不含特殊字符，URL 里免编码
  umask 077
  cat > "$path" <<EOF
APP_ENV=${app_env}
HOST=0.0.0.0
PORT=3940
POSTGRES_USER=trend_suite
POSTGRES_PASSWORD=${pw}
POSTGRES_DB=trend_suite
DOMAIN=${domain}
HTTP_PORT=${http_port}
HTTPS_PORT=${https_port}
TLS_ARG=${tls_arg}
EOF
  chmod 600 "$path"
}
gen_env <staging-deploy-path>/.env.staging staging    <staging-domain> 8080 8443 internal
gen_env <prod-deploy-path>/.env.prod     production <prod-domain>    80  443 ""
# ③ 自托管 runner 注册到本仓库（runner 按仓库注册，别处的不会自动出现）
TOKEN=$(gh api -X POST repos/<owner>/trend-suite/actions/runners/registration-token --jq .token)
./actions-runner_<ver>/config.sh --url https://github.com/<owner>/trend-suite --token "$TOKEN" \
  --name <runner-name> --labels self-hosted,macOS,ARM64 --work _work
docker buildx create --name ci-builder --use    # buildkitd 需配国内镜像源
```

**同时要满足**：服务器能拉镜像（root 的 `~/.docker/config.json` 备好仓库凭据，CI 只负责推）；云安全组放行预发端口（流水线健康检查在服务器内网做，不放行会「流水线全绿但浏览器打不开」）。

## 15. 限流基线

单实例固定窗口（60s），键为设备 ID / IP / 后台账号 / 设备码；内存表上限 10 万键，到上限先清过期窗口，仍满则拒绝新键（避免随机键撑爆内存）。超限统一 `429` + `Retry-After: 60`，**响应体不泄露配额细节**。

| 入口 | 键 | 配置 | 默认 |
|---|---|---|---|
| 设备码申请 / 设备码换令牌 / 设备批准 | IP / 设备码 / IP | `RATE_LIMIT_DEVICE_CODE_PER_MINUTE` / `DEVICE_TOKEN` / `DEVICE_APPROVE` | 10 / 120 / 10 |
| 令牌刷新 | 设备 ID | `RATE_LIMIT_REFRESH_PER_MINUTE` | 60 |
| 后台登录 / 邀请码兑换 / 门户注册 | IP | `RATE_LIMIT_LOGIN` / `INVITE` / `REGISTER` | 10 / 10 / 5 |
| 检索 | 设备 ID | `RATE_LIMIT_SEARCH_PER_MINUTE` | 120 |
| 目录与片段读取 | 设备 ID | `RATE_LIMIT_CATALOG_PER_MINUTE` | 240 |
| 进度上报 / 事件上报 | 设备 ID | `RATE_LIMIT_PROGRESS` / `EVENTS` | 120 / 120 |
| ASR 转写 | 设备 ID | `RATE_LIMIT_ASR_PER_MINUTE` | 20 |
| 播放会话 | 设备 ID | `PLAYBACK_MAX_CONCURRENT`（并发会话数） | 5 |
| 后台内容 / 管线 | 后台账号 | `RATE_LIMIT_CONTENT` / `PIPELINE` | 300 / 30 |
| AI 运营接口 | 后台账号 | `RATE_LIMIT_AI_PER_MINUTE` | 120 |

**扩多实例前必须把限流改为共享存储**（Redis/DB），否则配额按实例放大；当前部署保持单实例。

## 16. 安全与隐私基线

| 面 | 措施 |
|---|---|
| 传输 | 全站 HTTPS；媒体域同样 TLS |
| 凭据 | 设备令牌与会话令牌只存哈希；密码只存带盐 scrypt；签名密钥与对象存储密钥走密钥管理；不入日志/响应/镜像 |
| 账号 | 后台账号由管理员创建、学员自助注册；角色最小权限；门户会话 `scope=portal` 与后台隔离；禁用/改密吊销会话，禁用即时拒绝设备令牌 |
| 门户 | 公开页 ISR 缓存命中与失效（on-demand revalidate）；未知路径壳 `noindex`；公开接口只返回发布清单与聚合计数；下载强制 `attachment` |
| 内容 | 只下发 Top-K；播放地址与图示地址短时效、设备绑定（播放）或按文件限定（图示）；**不提供下载直链** |
| 内容管理 | `/v1/admin/content/*` 仅 operator/admin 会话；正文拒绝可执行 HTML/脚本；图片引用只认 `figure:<id>` 白名单格式；发布状态即时影响学员可见性 |
| 图示 | 提示词由服务端模板拼装；输出经类型/尺寸/内容校验；不生成写实行情截图与品牌标识；文件独立目录、单文件签名、不泄露本地路径 |
| 视频管线 | 上传先鉴权/限流再消费 body；`Content-Type` 与体积校验；ffmpeg/ffprobe 参数数组、**禁止 shell**；源路径/SHA/ffmpeg stderr/provider 响应不外泄；生成内容人工发布 |
| 模型密钥 | ASR、embedding、内容 LLM 密钥只存加密数据库；不序列化、不写日志/响应/镜像；内容 LLM 仅管理端调用 |
| 输入 | 白名单校验 + 长度/体积上限；拒绝非 JSON 与超大请求；ASR 路由单独 3MiB 上限并校验 WAV；上传路由单独 2GiB 流式上限 |
| 日志 | **不记 token、完整 query、完整 deviceId、源路径、转写正文、provider 响应**；排障用截断前缀或哈希；结构化日志带 `request_id`，响应回传 `request_id` |
| 隐私 | 数据最小化；事件需同意且可撤回；支持数据删除；学员语音音频与转写不落盘、不落日志、不进指标；生产不使用第三方分析 SDK |
| 额度 | 明细不含问题原文；账本只追加不修改，冲正用反向行 |
