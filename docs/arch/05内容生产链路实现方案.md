# 05 内容生产链路实现方案

关联：[01 整体架构设计](01整体架构设计.md) · [02 云端服务架构](02云端服务架构.md) · [03 数据存储设计](03数据存储设计.md) · [06 教材呈现与交互课件实现方案](06教材呈现与交互课件实现方案.md)

> 本文回答「一段原始视频怎么变成可发布的课程与教材」。
> 覆盖链路：**直传上传 → 存储 → 媒体校验 → 转码 → ASR 转写 → 关键帧/帧轨道 → 多模态理解 → 课程综合（门禁①）→ 逐节九步生产 → 三层校验 → 评审（门禁②）→ 签批与发布**。
---

## 1. 链路总览

```
浏览器拖入视频
  │ ① 建素材 + 签发直传凭据（HMAC 绑定 assetId/字节数/摘要/有效期）
  ▼
浏览器 PUT 字节 ──► 存储：sources/<assetId>/source（临时文件 → 原子 rename）
  │ ② 落库确认（sha256 校验、状态 uploaded）→ 入队 ingest 任务
  ▼
云端 pipeline worker：probe → transcode(HLS+PCM) → keyframes → transcribe → finalize
  ▼
理解 Agent：转写分组 + 采样帧 → source units
  ▼
综合 Agent：目录先验校验 + 概念归一 + 制作方案 ──► 门禁①（教师三动作）
  ▼
逐节子代理 ×N（九步固定顺序）→ 三层校验 → 评审 Agent（门禁②）
  ▼
就绪度（五道门禁）→ 运营签批（内容指纹）→ 发布（draft→published）
```

**阶段间只靠 DB 状态与文件产物交接**：任一阶段崩溃，重跑按幂等规则复用已有产物（已探测时长、已提升 HLS、成功 ASR 块、已完成 step）。

## 2. 角色分工

| 角色 | 职责 | 执行方 |
|---|---|---|
| 理解 Agent | 多模态逐 chunk 处理素材（转写分组 + 采样帧），产出 source units | 云端 worker（VLM 调用平台模型） |
| 综合 Agent | 目录先验校验、概念归一、起草制作方案（含分节计划）、支持打回重起草 | 云端 worker |
| 逐节子代理 ×N | 每节一个并行子代理，按九步固定顺序生产 | 云端 worker（受并行度上限约束） |
| 主编评审 Agent | rubric 十维自评，产出逐段修改指令 | 云端 worker |

**模型调用全部走云端模型配置**（任务级主备、密钥加密、预算硬停）——教师零密钥。

### 2.1 云端 Agent 技术栈

编排搬到云端后，**云端必须自己提供一个能运行的 agent**：能分析任务、自主多轮调用 skill/tool、产出可校验的 spec——而不是一次 LLM 调用。

#### 2.1.1 能力清单（从需求倒推）

| 需求（来源） | 对 agent 运行时的要求 |
|---|---|
| 九步固定顺序、跑错序被挡（教师端需求 T10 验收） | 编排由**确定性状态机**掌控，agent 只在本步内决策 |
| 每节一个并行子代理（教师端需求 T10） | 并行 agent + 子代理委派 |
| 方案三动作、评审 reject（教师端需求 T8 / T12） | **人机协同中断与恢复**（HITL interrupt → 教师裁决 → resume） |
| 崩溃恢复、断点续跑（非功能） | agent 会话可持久化、可 resume |
| 工艺包热迭代 | skill 载体（目录 + 模型可见的 skill 加载） |
| 21 个 `cloud_*` 类确定性工具（同类实现已在用） | 工具注册 + 确定性执行 + 结果回填 |
| 成本与溯源（非功能） | token 计量 + 预算硬停 + 逐产物溯源 |
| 多厂商模型 + 任务级主备（见 07 §9） | **provider-neutral** 模型接口 + 我们自己的路由与记账 |

#### 2.1.2 技术选型：deepagents（npm TS 版，进程内）+ 我们的确定性状态机

deepagents 的官方 TypeScript 实现（npm `deepagents`，MIT，`langchain-ai/deepagentsjs`）**与 Python 版功能对等**：`createDeepAgent({ model, tools, systemPrompt, middleware, subagents, skills, backend, interruptOn, checkpointer, permissions, memory, ... })`，其中：

- `model` 接受 **`BaseLanguageModel` 实例**（任意自定义 `BaseChatModel` 可传入）→ 我们的 provider adapter 原生接入；
- `interruptOn` 逐工具 HITL（approve/edit/reject），恢复用 `new Command({ resume: { decisions } })`，**恢复状态按 checkpointer + thread_id 键控、与 agent 实例无关**（中断后换一个 agent 实例共享 checkpointer 即可续跑）；
- skills 渐进披露与 Python 版同构：SKILL.md 发现（YAML frontmatter）→ 系统提示只注入名称+描述 → 模型按需 `read_file` 加载 → 工具按披露门控；
- `CompositeBackend` / `FilesystemBackend` / `StateBackend` 同名同义；
- checkpointer 兼容 LangGraph.js 生态（`@langchain/langgraph-checkpoint-postgres@1.1.4`，MIT）；
- peer：`@langchain/langgraph ^1.6.1`、`@langchain/core ^1.3.7`、`langchain ^1.6.4`（deepagents 实际版本 **1.17.0**，其依赖树自带 zod ^4 与仓内 zod ^3 嵌套共存，见 §2.1.4 SP1 结论——**仓内契约层维持 zod ^3 不动**，agent 工具 schema 用 `zod/v4` 子路径）。

| 层 | 选型 | 理由 |
|---|---|---|
| 编排层 | **我们的确定性九步状态机**（Next.js 服务同进程，DB 队列 + step 级 checkpoint + 三层校验 + 回灌 + 门禁） | 顺序纪律是需求写死的；崩溃恢复不依赖框架私有状态 |
| 步内 agent 执行面 | **deepagents（npm TS 版）进程内组装**：`createDeepAgent({ model, tools, subagents, skills, backend, interruptOn, checkpointer })` | 与 Python 版能力对等，**云端保持 TS 单栈**——不需要 Python 子服务、不引入第二套部署与测试 |
| 模型通道 | **我们的 provider adapter 实现为 `BaseChatModel` 子类**：**openai 兼容 + anthropic 双协议**（工具调用与流式的协议映射见 [07 §9.1](07平台服务方案.md)）；密钥自 `ai_models` 解密；内部做任务级主备（可跨协议）、冷却、token 计量、`ai_usage_events` 记账、预算硬停 | 框架只管流程，**模型路由与成本必须在我们手里**（07 §9/§10） |
| 工具层 | **我们的确定性工具集**（检索 units / 取行情 / 读术语与案例股 / 写草稿产物），注册为 LangChain tools；错误返回 `{"error":...}` 不中断循环；参数宽容归一（Postel） | 工具即云端服务能力（§3、06 §5）；adapter 只做协议适配，不写业务 |
| 工艺(skill)层 | `skills/<name>/SKILL.md`（frontmatter）+ `CompositeBackend` 只读路由（`/skills/` → FilesystemBackend）+ 写权限 deny + 渐进披露；版本随产物记 `skillVersions` | 与 dsh 的 SKILL.md 形态同源；与我们的服务端版本化工艺配置一致 |
| 人机协同 | `interruptOn`（门禁①②的中断点）→ 状态机挂起 + 工作台审批 → `Command({ resume })` 续跑同 thread | 门禁是我们自己的业务语义；HITL 机制现成且按 thread_id 键控，适配 worker 轮换 |
| 持久化 | **我们的 PG 为权威**（`production_tasks` step checkpoint）；agent 会话由 `@langchain/langgraph-checkpoint-postgres` 承载，`thread_id = (courseId, sectionId, step)` 关联 | 崩溃恢复不依赖框架私有状态；会话历史可审计、可级联清理 |

**进程内集成（无子服务契约）**：deepagents 与状态机同进程——状态机按 step 直接 `invoke`/`stream` deepagents 图（传 `config.configurable.thread_id`），产物候选 spec + 依据（citations/assertions）由 TS 引擎做确定性校验（不由模型裁决）；失败/取消按稳定 code 映射到重试/回灌/待办；事件与进度一律由**工具调用映射**产生（确定性、可回放）——不经 CLI 子进程、不做手写 SSE 协议、不按输出长度推断进度（对齐 §3.8）。

若 TS 版出现能力缺口，回退路径是独立的 Python deepagents 子服务——切换只影响步内执行面的部署形态，不动状态机、契约与 UI。

#### 2.1.3 步内 agent 形态

每个角色的一步不是一次 LLM 调用，而是一个**有界 agent 运行**：

```
步骤开始（状态机给出目标、输入、可用工具清单、必守断言）
  → 规划：产出本步子任务（可先调 skill 工具加载对应工艺）
  → 执行：自主多轮「模型 → 工具 → 结果回填 → 模型」，直到产出候选 spec
  → 自检：模型自述依据（citations / assertions）
  → 确定性校验（schema → 语义 → 教学质量）——由我们的引擎执行，不由模型裁决
  → 通过则落产物并推进状态机；失败则回灌（≤3 次）或转人工待办
```

- **智能分析任务**：规划段 + 可用工具承担（先查 source units / 术语表 / 案例股清单再动笔），不是把输入全塞进一次提示词。
- **skill**：模型按需调用 skill 工具加载工艺（如"分节写作工艺"），加载记录进溯源的 `skillVersions`。
- **终止条件**：由状态机给出（"产出满足断言的 spec"或"本轮预算耗尽"），agent 不得自行决定跳过步骤。

| SP6 | **HITL 门禁**：`interruptOn` → 状态机挂起 → 工作台审批 → `Command({resume})` | 审批决定持久化；恢复后不重复已完成步骤 | ✓ `interruptOn:{toolName:true}` → 首次 invoke 返回 `__interrupt__`（`actionRequests[{name,args}]`）；**interrupt 必须配 checkpointer + thread_id**（无 checkpointer 直接 GraphValueError，中断持久化是硬前提）；resume 格式 `Command({ resume: { decisions: [{type:'approve'\|'edit'\|'reject', ...}] } })`，resume 后工具真实执行、后续轮次不重复 |

### 2.2 前端对话 UI 适配（assistant-ui）

对话类界面（教师工作台的生产看板对话/评审卡/待办、学员端问答）统一用 **assistant-ui**，与后端框架解耦：

| 端 | 适配方式 |
|---|---|
| 教师工作台（浏览器，云端 Next.js 页面） | 后端把 deepagents 的 `astream` 输出转成 **langgraph-sdk 兼容 SSE 帧**（`messages\|ns` / `updates\|ns` / `custom` / `end` / `error`），经 Next.js Route Handler（Node runtime，`ReadableStream` + `no-store`）推送；前端 `@assistant-ui/react-langgraph` 的 `useLangGraphRuntime` 直接可用；审批卡/决策卡用自定义 tool UI 渲染（HITL 点选） |
| 学员端（DSH 插件 Browser 半 React） | 用 assistant-ui 组件渲染问答/引用/工具卡；runtime 走**自研 DSH Remote adapter**（plugin host ↔ browser 半），不直连云端 SSE（学员端问答在云端，但消息面经 DSH Remote 协议） |

- 组件基线：`ThreadPrimitive` / `MessagePrimitive`（content part 分流：Text=Markdown、Reasoning=折叠思考块、ToolCall=状态卡）+ `Composer`；引用片段用自定义 content part 渲染为可点 chips。
- 门禁①②的"三动作/评审卡"用 assistant-ui 的 **HITL interrupt UI**（用户点选后 `respond` 回填），不用自绘按钮组。

## 3. 阶段一：媒体与素材管线

### 3.1 直传上传（教师端需求 T4）

| 项 | 规则 |
|---|---|
| 建素材 | `POST /v1/admin/content/media-assets` → 返回 `assetId` 与直传凭据 |
| 凭据 | HMAC 签名，绑定 `assetId + 字节数 + sha256 + 有效期`；服务端只验签不中转字节 |
| 上传 | 浏览器 `PUT` 字节到存储直传地址；**不经业务进程内存** |
| 限值 | 单文件 ≤ 2GiB；Content-Type 仅 `application/octet-stream`；超限 `413`、类型不符 `415` |
| 摘要 | 可选 `x-file-sha256`（64 位小写 hex）；流式计算，不符 `400` 并删除半成品 |
| 状态 | `awaiting_upload → uploaded`；重复上传覆盖旧源并重置转写/生成 |
| 音轨校验 | 必须同时存在视频流与音频流，否则拒绝并清理半成品 |
| 体验 | 进度可见、可重试 |

服务端路由级 `bodyLimit = 2GiB`；`preParsing` 先完成会话鉴权与限流再消费 body。

**实现现状（迭代 1，2026-11）**：直传目标由 `MediaStore` 实现给出，两种实现同一接口：

- `MEDIA_STORAGE=local`：直传地址是应用自身的 `PUT /v1/admin/content/media-assets/{id}/upload`。字节**流式落盘**（边收边写暂存位，不在内存里攒全量），这是本地文件系统模式下的等价形态——「不经业务进程内存中转」指的是不在内存缓冲整份文件；对象存储模式才是真正的浏览器直传。
- `MEDIA_STORAGE=cos`：**骨架未启用**。桶与凭据到位前 `CosMediaStore` 的每个方法都抛「未接入」（路由层映射 503）。真正启用还差四件事：SigV4 预签名 PUT、桶 CORS、probe 取样（下载到 `/data` 再跑 ffprobe）、半成品对象清理。

直传凭据签名密钥走 `MEDIA_UPLOAD_SECRET`（env 注入，不入库）；未配置时上传接口返回 503，不静默放行。

**凭据有效期必须落库**（`media_assets.upload_expires_at`）：签名把「素材 + 字节数 + 摘要 + 到期点」绑成一个 HMAC，签发时算一次、校验时再算一次——两端各自现算必然算岔（毫秒都不同），凭据就永远验不过。到期点存在库里，两端读同一行才算得出同一个值；重试复用素材时重开到期点，让重试拿到新凭据而不是抱着过期的那张。

### 3.2 存储布局与抽象

```text
workspace/pipeline/            # 容器内挂载为 /data
  storage/                     # MEDIA_STORAGE_DIR
    sources/<assetId>/source   # 原始上传字节（只读）
    work/<assetId>/{audio.wav, chunks/, hls/, keyframes/}
  hls/                         # PIPELINE_HLS_DIR（与 storage 同卷）
    hls/<assetId>/{index.m3u8, seg_00000.ts}
  figures/                     # FIGURE_DIR：figures/<figureId>/<candidateId>.jpg
```

- **存储定案**：生产用**对象存储 COS**（与部署机同地域，内网读写免流量费；桶私有读）；`MEDIA_STORAGE=local`（本地文件系统）仅用于开发与测试。原始视频、HLS、关键帧图示**全部进同一桶**，对象键与 `hls_path` / figure 路径一一对应。**桶与凭据尚未开通，两个环境暂时跑 `local`**（compose 已挂 `/media` 落盘，媒体字节不进应用镜像）；桶一到位即切 `cos`，接口不变、只换实现。
- **`MediaStore` 接口**：建目录、流式写、SHA-256、原子提交、清理、HLS 校验；实现两种：COS（S3 兼容 + SigV4 预签名）与本地文件系统。接口不变，切换只换实现。
- **local 模式的实际布局**：`MEDIA_STORAGE=local` 时原始字节落在 `MEDIA_LOCAL_DIR`（容器内 `/media`）下：`staging/<assetId>/upload`（收流暂存）→ 校验通过后同卷 `rename` 到 `sources/<assetId>/source`（正式位）。清理分两级：上传中断或字节数不符只清暂存位（`discard`，素材行留着可重试，不动已提交的正式位）；素材行作废才连正式位一起删（`remove`）。
- **服务器磁盘只做管线临时工作区**：转码/抽帧在 `workspace/pipeline`（容器内 `/data`）进行，产物**上传 COS 后即清理本地副本**——服务器不长期保存任何媒体字节，磁盘只按「单 asset 在制峰值」规划（数十 GB 级），不按语料总量规划。
- **提交语义**：本地模式 HLS 从 `work/<assetId>/hls` **原子 rename** 到 `hls/<assetId>`（同卷，跨卷即失败，不复制降级）；COS 模式先在临时卷内 rename 完成、完整性校验通过后整目录上传，上传成功才写 `media_assets` 落库。
- **签名范围隔离**：`media_assets.hls_path = 'hls/<assetId>/index.m3u8'`，播放签名只覆盖该前缀，**源文件（`sources/`）永不进入签名范围**；图示按单文件签发，不能靠换 figureId 越权读取。
- **播放直连**：按节签名会话签发 **COS 预签名地址**（m3u8 与分片一并覆盖，有效期=播放窗）；浏览器直连 COS/CDN 拉流，**媒体字节不经云端应用**。窗校验即预签名时效；水印为播放器叠加层。

### 3.3 媒体校验（probe）

```
ffprobe -v error -print_format json -show_format -show_streams
```

| 检查 | 失败 |
|---|---|
| 存在视频流 **且** 存在音频流 | `422`（终态失败） |
| 时长 > 0 且 ≤ `PIPELINE_MAX_SOURCE_SECONDS`（默认 14400s = 4h） | `422` |
| 媒体损坏/无法解析 | `422`，仅返回稳定 `error_code` |

### 3.4 转码与抽帧（ffmpeg）

档位定案：**单一 720p 档**起步（约 0.5–1 GB/h）；加档只改转码模板，不影响存储结构与对象键。固定参数模板（**只 `spawn(FFMPEG_PATH, args)`，禁止 shell**；启动探活 `-version` 5s，缺失即启动失败）：

```bash
# HLS：单码率 H.264/AAC，6s 分片，VOD
ffmpeg -y -i source \
  -c:v libx264 -preset veryfast -crf 23 -pix_fmt yuv420p -vf "scale='min(1280,iw)':-2" \
  -c:a aac -b:a 128k -ar 48000 \
  -f hls -hls_time 6 -hls_playlist_type vod -hls_segment_filename 'seg_%05d.ts' \
  -progress pipe:1 index.m3u8

# 16kHz 单声道 PCM16（供 ASR）
ffmpeg -y -i source -vn -ac 1 -ar 16000 -c:a pcm_s16le audio.wav

# 静音检测（只读 stderr）
ffmpeg -y -i audio.wav -af silencedetect=noise=-30dB:d=0.5 -f null -

# 切块
ffmpeg -y -ss <start> -t <duration> -i audio.wav -c:a pcm_s16le chunk.wav

# 关键帧：按图示计划时间点抽单帧，最长边 ≤1600
ffmpeg -y -ss <sec> -i source -frames:v 1 -vf "scale='min(1600,iw)':-2" -q:v 2 keyframes/<sec>.jpg
```

- 进度：解析 `-progress pipe:1` 的 `out_time_ms`；超时 `PIPELINE_FFMPEG_TIMEOUT_MS` / `PIPELINE_AUDIO_TIMEOUT_MS`；取消时 `SIGKILL` 子进程并清理工作区；stderr 只进内部日志，不回客户端。
- 发布前校验：playlist 存在 `#EXT-X-ENDLIST`、全部分片存在且非空，再原子 rename 到 HLS 目录。

**ffmpeg 8.x 实现口径**（版本差异写死，避免按旧语法踩坑）：

| 事项 | 口径 |
|---|---|
| 场景检测 | ffmpeg 8.1 已移除 `select` 的 `scene` 变量 → 改用 `scdet=threshold=8` + `metadata=print` 解析 `lavfi.scd.time` |
| 画质统计 | `signalstats` 读 `YAVG`/`YHIGH`/`YLOW`；对比度取 `YHIGH−YLOW` |
| mjpeg 输出 | 经 `filter_complex` 输出 JPEG 需先 `format=yuvj420p`，否则像素格式不被接受 |
| 一次解码 | 抽帧用 `split` 分三条支线（fps 基线采样 / signalstats 统计 / scdet 切点），避免重复解码原片 |
| HLS 转码档 | **迭代 6 已启用**（`server/pipeline/processing/transcode.ts`）：单码率 H.264/AAC 6s 分片 VOD，转完校验 `#EXT-X-ENDLIST` + 全部分片存在且非空，再原子 rename 到 HLS 目录并落 `hls_path`；幂等——`hls_path` 非空且分片在盘即跳过（存量 ready 素材非 force 重跑即补 HLS）；失败抛 retryable `ProcessingError`，只补 HLS 不重跑转写与抽帧 |

### 3.5 ASR 转写

| 步骤 | 规则 |
|---|---|
| 切点 | 静音检测（-30dB / 0.5s）得到切点，按 ≤`PIPELINE_CHUNK_SECONDS`（默认 480s）切块，切点吸附最近的静音点 |
| 单请求上限 | 上游单请求音频 ≤500s，超限**直接 400 不截断** → 必须在客户端切块，切块上限取 480s 留余量 |
| 并发 | 最多 `PIPELINE_ASR_CONCURRENCY`（默认 2）并发；每块**独立缓存**，重跑直接复用（避免重复计费） |
| 调用 | 平台 ASR（模型配置页维护）：`protocol=minimax` → `POST {baseUrl}/v1/speech_to_text`（`response_format=verbose_json` + `timestamp_level=sentence`）；`protocol=openai` → `POST {baseUrl}/audio/transcriptions`；解析器兼容 `sentences/segments/utterances` 与多种时间键（含独立 `start_ms`/`end_ms`） |
| 重试 | 每块最多 3 次（429/5xx/网络），退避 2s/4s/6s；仍失败则该块 `failed`（终态，任务失败不吞） |
| 兜底 | 无时间戳时退化为「整块一句话」，时长按块长估算 |
| 拼接 | 块内局部毫秒 + 块起点 → 全局时间戳；丢弃空白/重叠；按 ≤30s 分组写 `transcript_segments`；时间戳必须单调不重叠 |
| 落库节奏 | 每转完一块即**单事务**写入该块段落（`partial=true`、`chunk_index=块号`）；全部块完成后统一重排连续 `seq`（两趟改写避免撞 `(asset_id, seq)` 唯一约束）并置 `partial=false` 定稿 |
| 隐私 | 转写正文只存 DB；仅管理端接口可取；日志与指标不记正文 |

**增量可见**：每转完一块即落可读段落（`partial=true`），工作台可读、理解与生产提前起跑（教师端需求 T5 验收项）。

**重跑不重复计费**：已转块以 `transcript_segments.chunk_index` 为准——该块已有段落就整块跳过，不再调 ASR。

### 3.6 关键帧与帧轨道

- 落盘：采样帧先落加工工作区，定型后挪到媒体存储的持久帧目录——**两者在生产容器分属不同挂载卷**，移动必须走「rename 失败 EXDEV 回退复制+删源」，直接 rename 在线上必炸（本地开发同盘无感）。

- 采样：ingest 时**场景检测 + 1 帧/15s** 采样，去重后存 `work/<assetId>/keyframes/`；云端只抽帧，**不做视觉理解**（理解在 §4）。
- 补帧：图示计划（`sourceHint` 时间点）需要时按时间点单帧抽取，最长边 ≤1600；`sec` 必须落在所引 source unit 时间范围内（复检 `sec_not_grounded`）。
- 质量门：抽帧结果校验**非纯色/非黑屏**——亮度 `YAVG ∈ [24, 240]` 且对比度 `YHIGH−YLOW ≥ 12`，不合格直接丢弃并降级为 `generated` 图示。
- 去重：两帧时间距离 <3s 视为重复，只留一张；总数受 `PIPELINE_MAX_FRAMES` 约束。
- 访问：`GET /v1/admin/content/media-assets/{assetId}/frames?from&to` 返回**短时签名帧 URL**（供生产端 VLM 消费）。

### 3.7 ingest 任务编排

- 阶段序列：`audio → transcribe → transcode → frames → understand → index → done`（转写优先于 HLS——教师等的是逐字稿）；队列与 worker 状态机见 [02 云端服务架构](02云端服务架构.md) §4。
- 素材状态机：`awaiting_upload → uploaded → processing → ready`，失败 `failed`；失败原因落 `media_assets.error_code`/`error_message`，`process_step` **保留失败时所在阶段**（不写 `failed`/`canceled` 这类非法阶段值——阶段枚举只有 `uploaded/audio/transcribe/frames/index/done`）。
- 幂等：已转块按 `chunk_index` 跳过（不重复计费）；关键帧按 `(asset_id, at_ms)` 刷新不重复；段落一次性写；重复 ingest 返回原状态。
- 取消：queued 立即取消；running 置 `cancel_requested`，worker 在阶段边界检查并中止 fetch / `SIGKILL` ffmpeg；素材退回 `uploaded`（可重新加工），已产生的块保留供重试。没有进行中任务的素材点停止返回 `409 material_not_processing`。
- 删除：素材行、转写段落、关键帧、任务与已落盘字节一并清理（`pipeline_jobs` / `transcript_segments` / `media_frames` 外键 CASCADE）；正在加工的先停止再删；已产出理解成果（source units）的素材拒绝删除（`409 material_referenced`），须先处置方案引用。
- 失败重试：任务失败后素材回 `uploaded` 可重新入队；已转块与已抽帧保留，**不重算已完成部分**。

### 3.8 管线错误映射

| 状态 | 场景 |
|---|---|
| `400` | 参数/ID 非法；SHA 不符 |
| `401/403` | 未登录；角色不足或设备不匹配 |
| `404` | 素材/任务不存在 |
| `409` | 状态不允许（重复 ingest、素材已有产物） |
| `413/415` | 上传超限；Content-Type 非 octet-stream |
| `422` | 媒体无音轨 / 超时长 / 损坏；源文件缺失 |
| `429` | 管线接口限流 |
| `503` | 管线未启用、ffmpeg 不可用、ASR/模型未配置 |

客户端只见稳定 `error_code`（≤64 字符）与静态文案，内部 stderr 不外泄。

## 4. 阶段二：多模态理解

- 输入：转写分组（5–10 分钟 chunk）+ 该 chunk 时间窗内的采样帧。
- 输出 source unit：`{时间范围, 转写, 画面描述, 图表类型, 讲解要点, 关键帧引用}`。
- 幂等：`(asset_id, start_ms)` 唯一；重跑按缺失 chunk 补齐，不重算已有。
- 帧描述质量纳入 rubric 评估集（描述失真算 grounded 失败）。

**迭代 6 实现落位（`server/pipeline/processing/understand.ts`）**：

- **分组口径**：按 `transcript_segments.chunk_index` 分组（即转写块），每块一次 VLM 调用；帧采样按该块时间窗 ±15s 边距窗内优先、窗外则全程均匀兜底，每块 ≤6 帧。
- **调用**：多模态消息走 openai 协议的 content 数组（text + image_url），任务键 `vision.describe`、用途 `vlm`；`ai_runs` 计量。
- **落库**：单事务批量写 `source_units`（理解产物的迭代面走 `extra` jsonb：图表类型/讲解要点/关键帧引用），并回填 `transcript_segments.unit_id`。
- **幂等**：已完成 chunk 只补缺失块，重跑不打模型。
- **失败不阻断 ready**：VLM 挂了素材照常 ready（转写/帧/HLS 已成），该素材只是「未理解」；生产步骤查不到 evidence units 时该节明确失败（`no_source_units`），不阻断教师回看素材。

|---|---|
| 目录先验 | 以人工目录（篇→卷→课时）为骨架；**不允许发明目录**（目录外章节不创建） |
| 概念归一 | 跨课时抽取概念 → 聚类合并 → `concepts`（含别名）+ `concept_edges`（`prerequisite` 标注教学依赖序） |
| 术语表 | `concepts.name` 为正文与课件 spec 的术语校验基准；未收录术语在第 2 层校验被拒 |
| 匹配度 | 某节证据不足（匹配度低于阈值）→ 该节标红并给匹配度，教师裁决「修订提纲」或「补充素材」，**其余节不受影响** |

### 门禁①：方案确认（工作台审批组件，三动作）

| 动作 | 语义 |
|---|---|
| 批准 | 方案锁定为基准版，解锁逐节生产 |
| 微调 | 直接结构化编辑方案条目（章节增删合并 / 改名 / 概念别名 / 分节粒度），即时生效 |

方案草案与人工修改留版本轨迹（v1 → v2 …）；确认后锁定，中途变更走「追加素材 B 重做骨架」。

### 5.1 实现状态（迭代 3 已落地）

- **目录先验**：人工目录（教师提交的原文，正则解析三级编号）是骨架的唯一来源——骨架 = 目录全量节点（目录是下界，模型漏掉的节点保留并判「证据不足」）；模型自造的章节 id 剔出骨架并进 `violations`（`outline_violation`），不创建章节。
- **目录可代拟**（原型口径「目录先验（可选）」）：教师只交课程目标时，worker 先按目标与素材语料让模型代拟一版结构化目录（篇/章/课时），再由 `buildOutlineFromSections`（contracts outline.ts）生成规范文本与目录树——**文本与树同源**，代拟结果回写 `courses.outline` / `outline_text`，之后以该版为目录先验走综合起草；教师可在「改目标与目录」里改写后重提。模型未拟出任何章节时任务终态失败（`outline_draft_empty`），不产出空骨架。
- **代拟目录的 token 预算与规模约束**（生产实测踩坑后定档）：推理型模型（M3.1-Flash）的思考与正文**共用 `max_tokens` 预算**，代拟目录的 4K 上限被思考吃光 → `stop_reason=max_tokens` 截断、JSON 不完整、任务终态失败。上限提到 12K（综合起草那步 32K），提示词同时约束规模（≤3 篇 / 每篇 ≤8 章 / 每章 ≤8 课时 / 总计 ≤40 条 / 标题 ≤20 字），schema 再兜一层 ≤200 条。**截断判可重试**（`llm_truncated` retryable，思考长度每次不同，重试往往就过）；失败调用的用量照样入 `ai_runs` / `ai_usage_events`（上游已回的 usage 不能不算，重试要花钱）。
- **综合起草的 token 预算**（同上教训的第二次落地）：40 条目录的综合起草在 16K 上限下**连续三次撞满 16000**（思考把预算吃光 → JSON 截断）。上限提到 **32K**，提示词同步给规模上限（matches 恰好覆盖目录节点 / concepts ≤25 且定义 ≤40 字 / edges ≤30 / lessons 只为课时级章节且 ≤40 条）——预算给足 + 产出收窄，两头一起压。
- **Agent 执行轨迹与工作台 Agent 面板**（对齐原型 teacher-plan 的 agent-rail）：方案页右侧常驻 Agent 面板，三个页签——「对话」讲过程、「执行」列步骤与模型调用、「产物」列方案文件。轨迹**不另存一份**，由既有台账现算：步骤 = 队列进度（`pipeline_jobs.step`）+ 目录/起草两段的模型调用状态，调用明细 = `ai_runs`（阶段由 `summary` 前缀 `outline:` / `draft:` 标记，调用方经 `runLlmJson` 的 `phase` 参数写入），产物 = 方案行的四件套计数。面板只呈现真相，不造状态。
- **解析规则单一真相源**：目录编号格式与规整规则落在 `packages/contracts/src/outline.ts`（前后端共用）——服务端据此把关（认不出的行 400 并带行号），教师端据此本地逐行标红与一键规整（需求 T6「可粘贴、可口述」：常见写法如「第一部分 / 一. / 1 xxx / （1）xxx」自动改写为三级编号，认不出层级的行按上文顺推补编号）。规整只改编号形式、不动标题原文。
- **概念归一**：模型给的是概念**名**，服务端归一——重名只留首个并记 `concept_conflict`；别名与别的概念名撞车时剔除别名；自环/重复边剔除；`prerequisite` 成环时环内边剔除并留痕。草案期概念只存 `course_plans.concept_map`（jsonb），**批准时才落 `concepts` / `concept_edges` 表**（重名由 `UNIQUE(course_id, name)` 兜底，409）；术语表与概念图谱同源，别名同步。
- **匹配度**：阈值 0.5（前后端常量，不落库）；低于阈值的节点标红并给匹配度，教师裁决「修订提纲」或「补充素材」，**其余节不受影响**。
- **服务端门禁**：批准动作在服务端挡未决项——存在「证据不足」节点或任何 `violations` 时返回 409 `plan_unresolved`（UI 禁用只是第一层）。
- **状态机**：起草（队列，job kind `curriculum_draft`）→ 批准（锁定基准版）→ 打回（旧行 rejected + 新 draft 版本 +1，只重新综合、**不重跑素材理解**）→ 微调（结构化纯函数，即时生效、版本 +1、不调模型）。概念别名微调在已批准态同步概念表。
- **队列通用化**：`pipeline_jobs` 任务引用素材维度或课程维度二选一，活跃唯一索引 `(COALESCE(asset_id, course_id), kind)`——素材任务与课程任务并存认领互不干扰。
- **就绪度门禁**：素材未全部就绪（`allowPartial` 本迭代不开放）→ 409 `plan_not_draftable`，不可触发起草。
- **落位**：方案状态机在 `server/content/plans/`（轨迹构建器 `plans/trace.ts`），模型通道在 `server/content/agents/`；浏览器侧面板归入 `features/content/ui/`（`server/content` 的同名配对域，不另开 `features/plans`），路由 `/v1/admin/content/courses/[id]/plan*` 沿用内容路由族。

## 6. 阶段四：逐节生产（九步固定顺序）

引擎**强制顺序**，跑错序被挡并提示当前步：

| # | 步骤 | 产出 / 约束 |
|---|---|---|
| 1 | 案例股 | 本节案例股清单（代码/窗口/事件锚点），云端复检 |
| 2 | 行情同步 | 按节声明周期拉取行情缓存（幂等 upsert），未就绪显式占位 |
| 3 | 行情读回 | 读回确认（口径/交易日/窗口），失败降级为占位，**不伪造数据** |
| 4 | 图示 | 三路分工（§8），配额：keyframe ≤6/节、diagram ≤2/节 |
| 5 | 回放课件 | 逐根回放 spec（`bar-replay-decision`），断言必须可证明（06 文档） |
| 6 | 正文 | grounded 写作（Markdown + DSL），1200–3000 字；事实段带 `[[unit:]]` 锚 |
| 7 | 其余课件 | mcq-quiz / pattern-quiz / flashcards / checklist / timeline-explorer / calc-trainer 等 |
| 8 | 评审 | rubric 十维自评 → approve / reject + 逐段修改指令 |

- 并行：逐节子代理并行，**单课并行度上限可配**（起步 3–4 节），单课生产不阻塞其他课。
- 断点续跑：checkpoint 落 DB（按 step），worker 崩溃恢复不依赖本地状态。
- 章节正文结构（`chapter-authoring` 工艺固化）：概念 → 判断依据 → 实例 → 检查清单 → 常见误用。

**迭代 4 实现落位（骨架 + 占位级产物，九步步序/键已冻结在 `server/production/steps.ts`）**：

- **自动起跑**：批准方案事务内幂等预插 9×N 行 pending（`seedProduction`，ON CONFLICT DO NOTHING，断点语义：微调重批不复活既有节）+ 事务后入队 `production_run` job。
- **顺序强制是结构性的**：`claimNextStep` 只认领「更小步全 done」的最小 pending 行（CTE + `FOR UPDATE SKIP LOCKED`），跑错序根本认领不到，无需运行时校验报错。
- **执行面**：agent 步（1/4/5/6/7/8）走 deepagents 子代理——模型经 `TrendChatModel`（SP4 落产，见 arch/07 §9），占位产物只能经唯一工具 `write_step_output` 写入 `production_tasks.checkpoint`（工具 schema 即第一层校验，`zod/v4` 子路径）；pure 步（2/3/9）确定性函数不走模型。
- **回灌与挂起**：步失败 `attempts+1`，未达 `MAX_ATTEMPTS=3` 回 pending 重写，达上限转 `pending_manual` + `last_error`（看板「重试」入口：attempts 清零回 pending 重投 job）；预算触线（`AI_TOKEN_BUDGET_DAILY`，`budget_exhausted`）跳过回灌直接挂起，不产出无账本调用。单课节间并行冻结 `MAX_SECTIONS_PARALLEL=3`。
- **断点续跑双保险**：job 级 `reclaimStaleJobs` 心跳超时重投（测试注入 `WORKER_RECLAIM_STALE_SECS`）+ runner 起点无条件 `resetRunningTasks`（活跃 job 唯一索引保证单 runner，job 起点的 running 行必是孤儿认领）；agent 侧崩溃由 PG checkpointer 续跑同一步（thread_id=`courseId/sectionId/sN`，只作运行态缓存，权威状态在 production_tasks）。
- **验收**（迭代 4 五条 + 主备/预算/顺序单测，全部通过）：① 批准即起跑逐步推进 ② 一节挂起进度保留他节不受影响 ③ SIGKILL 重启 done 步不重跑 ④ 两课并行互不污染 ⑤ 终态无部分产物节（complete 节必配 9 done 步）。

**迭代 5 实现落位（步骤 1–3 从占位转真实：案例股与行情，数值可核）**：

- **步骤 1 案例股（真实）**：agent 按 arch/06 §5.1 要求产出 2–4 只案例股（6 位代码/名称/交易所/周期/时间窗/事件锚点 ≤5 个，schema 第一层校验）；云端复检 deterministic 二次校验（窗口合法、事件落窗）+ **自动归一**：1d 窗口早于 2024-03 → 改 1w 并记 note、交易所按代码前缀校正（不信任模型自报）。复检通过整节替换 `section_case_stocks`（事务内 delete+insert）；结构性违例走回灌（≤3 挂起）。**复检落库在 `server/content/quotes/service.ts`**。
- **步骤 2 行情同步（真实）**：逐股调腾讯前复权端点（`server/content/quotes/client.ts`，口径权威 = arch/06 §5；基址走 `MARKET_QUOTES_BASE_URL`），单页 640 根，`quote_bars` 幂等 upsert（(code,period,trade_date) 唯一、以源为准覆盖）。**源不可用 ≠ 步骤失败**：退避重试（1s/4s）后仍败 → 该股记 unavailable、不写 bar，步骤照常 done（发布可继续，绝不编造数值）。
- **步骤 3 行情读回（真实）**：直接读 `quote_bars` 缓存核对覆盖度（ok / partial / unavailable，按首末根与窗口容差判定）+ 事件锚点归一（event date → 窗口内 ≤ 原值的最后交易日，记录原值与归一值）。

- **看板产物面板**：节行「产物」展开 → 案例股卡 + K 线预览（`features/production/ui/KlineChart.tsx`，蜡烛+成交量+MA5/10/60+事件锚点竖线+悬停读数）；行情不可用显式占位框；常驻复权声明来自契约 `marketDeclaration` 单一事实源。
- **验收**（迭代 5 三条，全部通过）：① 落库 bars 与源 fixture 逐根相等（列序防错位单测）② 断源重跑零 bar + 显式占位、源恢复 resync 补数且步骤 1 不重付 ③ 声明字段契约化（浏览器目检）。另补：复检归一/结构性违例、锚点周六→周五归一、partial/unavailable/缓存语义、resync 409 单测。

**迭代 6 实现落位（步骤 4/6 从占位转真实：图示三路与教材正文，事实可回溯）**：

- **步骤 4 图示（真实）**：agent 产出三路 spec（keyframe 带 `unitId`/`secHint`、diagram 带模板与参数、generated 带提示词），云端复检并落库（`server/content/textbook/figures-service.ts`）：keyframe 按 unit 时间窗 ±2s 容差选帧、无帧则 ffmpeg 补抽单帧（`sec` 落窗外报 `sec_not_grounded`，取帧失败报 `figure_not_grounded`）；diagram 过模板白名单与参数 schema 后服务端确定性渲 SVG；generated 走文生图通道（§8）。**配额越界是阻塞性 issue**（keyframe ≤6、diagram ≤2），整步拒绝回灌且**一张都不落库**。落库按 `(course_id, section_id, kind, caption)` 覆盖更新——同节同 kind 同 caption 复用原 figureId，正文引用不失效。
- **步骤 6 正文（真实）**：agent 产出 `{markdown}`（全文含 DSL，五段结构：概念 → 判断依据 → 实例 → 检查清单 → 常见误用），云端复检两段（语法 → 语义全表，arch/06 §2.4）**全过才整列写入 `sections.body`**（`body_status='draft'`），任一 issue 即拒绝回灌——被拒正文**绝不部分落库**，原文留在 checkpoint 随拒绝原因喂回重写。术语校验点＝`:::sidenote` 的 title（必填且 ∈ 概念表 name+aliases，全词匹配），issue 带术语词、行列与「最接近的已收录术语」建议。
- **回灌语义的实测口径**：worker 单轮内对同一步连烧回灌预算（`attempts` 达 `MAX_ATTEMPTS=3` 即转 `pending_manual`），拒绝原因落 `last_error`（≤500 字），看板可见。
- **管理台预览页**：`/workbench/courses/[courseId]/production/sections/[sectionId]/preview`——正文按 DSL 现场渲染（v1 块全支持），`[[unit:]]` 锚点点开是内联的证据单元卡（时间窗/转写/画面描述/讲解要点），`[[stock:]]` 锚点联动案例股 K 线，片段卡走 HLS 播放，三路图示各有渲染（签帧 img / 内联 SVG / 生成图）。看板节行在 `body_status='draft'` 时亮出「预览」入口。
- **验收**（迭代 6 四条，全部通过）：① 一节正文成篇、五段结构与篇幅达标 ② 事实锚点可回溯到原始素材时间段 ③ 图示超配额被明确拒绝且不落库 ④ 概念表外术语该节被拦并说明原因（带最接近术语建议）。另补：DSL 解析/语义单测、管线 transcode/understand 单测、三路落库与覆盖语义单测。

| 层 | 位置 | 内容 | 失败处理 |

## 8. 图示三路

| 路 | 生成方式 | 教学承载 | 配额 |
|---|---|---|---|
| `diagram` | 模型出**结构化 spec**，服务端确定性渲染 SVG | 承载教学信息（标注文字 100% 正确） | ≤2/节，模板白名单 |
| `keyframe` | 按 source unit 时间戳取原始画面 | 承载讲师原始画面 | ≤6/节 |
| `generated` | 文生图（平台模型） | **仅装饰，禁止承载教学信息** | 每章 ≤3（课级 ≤24） |

- 禁止生成写实 K 线、收益曲线、行情截图或带品牌标识的假界面；提示词由服务端模板拼装，模型不得改写 `kind`、数量与安全约束。
- 图示下载后校验 JPEG/PNG、单张 ≤8MiB、边缘 ≥800px，再压缩落 `figures/<figureId>/<candidateId>.jpg`；记录 `prompt/model/seed`，用量记 `ai_usage_events.images`。

**迭代 6 实现落位**：

- **三路由一服务**：`figures-service.ts` 按 kind 分派——keyframe 取帧接地、diagram 渲 SVG、generated 调文生图；产出统一走覆盖 upsert（同节同 kind 同 caption 复用 figureId）。
- **generated 真做**：`server/content/agents/image.ts` 走独立图像端点（`POST {baseUrl}/v1/images/generations`，404 回落 `/v1/image_generation`）——**图像模型绝不走聊天端点**，任务键 `content.figure_generated`、用途 `image`，`ai_runs` 记 `kind='images'`。
- **失败语义**：图像模型未绑定（非 retryable）→ 步骤 4 不整步失败，generated 图**剔除 + note**（装饰图禁止承载教学信息，缺它不损 grounded）；配额（章 ≤3 / 课 ≤24）按 `section_id` 的章前缀在库内聚合计数，满额同样剔除 + note。
- **落地形态**：generated 图字节落 `figures/<figureId>/gen_<id>.jpg`，`figures.path` 记录；keyframe 的取帧结果记 `frame_id`，签帧 URL 复用既有帧签名通道。

## 12. 门禁、签批与内容指纹

### 五道发布门禁（一份实现）

发布就绪度与发布读**同一批检查结果**：

| 门禁 | 判定 |
|---|---|
| 图示解析 | 正文 `figure:` / `:::figure` 引用均可解析且候选就绪（`figure_unresolved`） |
| 课件断言 | 每个课件断言有证明记录（`widget_unproven`，附 widgetIds） |
| 片段窗 | 片段窗合法且落在已发布正文 clip 窗内（`clip_invalid`） |
| 标注与回放 | 标注引用有效（`annotation_unresolved`）、回放课件已证明（`replay_unproven`） |
| 终审签批 | 审批记录存在且指纹一致（`approval_required` / `approval_stale`） |

### 内容指纹

签批 = 对课程**内容指纹**签名，发布 = 重算指纹比对。覆盖：章节教材、节教材（dslVersion + markdown + citations 排序去重）、课件（id/type/specVersion/spec/assertions）、图示（id/kind/caption/assetId/sourceSec/spec）、节级案例股清单、片段（id/title/起止秒/text）。

- **改内容即已签批失效** → `approval_stale`，需重新签批（教师端需求 T14）。
- 顺序：内容完整性问题先于签名问题报错（前者可直接定位修）。

## 13. 溯源与用量

## 14. 预算与并发
