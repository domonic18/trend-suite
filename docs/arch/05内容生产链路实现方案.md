# 05 内容生产链路实现方案

版本：v1.0（2026-11-12）
关联：[01 整体架构设计](01整体架构设计.md) · [02 云端服务架构](02云端服务架构.md) · [03 数据存储设计](03数据存储设计.md) · [06 教材呈现与交互课件实现方案](06教材呈现与交互课件实现方案.md)

> 本文回答「一段原始视频怎么变成可发布的课程与教材」。
> 覆盖链路：**直传上传 → 存储 → 媒体校验 → 转码 → ASR 转写 → 关键帧/帧轨道 → 多模态理解 → 课程综合（门禁①）→ 逐节九步生产 → 三层校验 → 评审（门禁②）→ 签批与发布**。
> 继承说明：全链路的参数与状态机**继承 trend-studio 已跑通实现**（其 §6.4 / §6.5）；差异为教师端改浏览器直传（需求 B2）、生产执行位置改云端 worker（ADR-02）。

---

## 1. 链路总览

```
浏览器拖入视频
  │ ① 建素材 + 签发直传凭据（HMAC 绑定 assetId/字节数/摘要/有效期）
  ▼
浏览器 PUT 字节 ──► 存储：sources/<assetId>/source（临时文件 → 原子 rename）
  │ ② 落库确认（sha256 校验、状态 uploaded）→ 入队 ingest 任务
  ▼
云端 pipeline worker：probe → transcode(HLS+PCM) → keyframes → transcribe → finalize
  ▼
理解 Agent：转写分组 + 采样帧 → source units
  ▼
综合 Agent：目录先验校验 + 概念归一 + 制作方案 ──► 门禁①（教师三动作）
  ▼
逐节子代理 ×N（九步固定顺序）→ 三层校验 → 评审 Agent（门禁②）
  ▼
就绪度（五道门禁）→ 运营签批（内容指纹）→ 发布（draft→published）
```

**阶段间只靠 DB 状态与文件产物交接**：任一阶段崩溃，重跑按幂等规则复用已有产物（已探测时长、已提升 HLS、成功 ASR 块、已完成 step）。

## 2. 角色分工

| 角色 | 职责 | 执行方 |
|---|---|---|
| 理解 Agent | 多模态逐 chunk 处理素材（转写分组 + 采样帧），产出 source units | 云端 worker（VLM 调用平台模型） |
| 综合 Agent | 目录先验校验、概念归一、起草制作方案（含分节计划）、支持打回重起草 | 云端 worker |
| 逐节子代理 ×N | 每节一个并行子代理，按九步固定顺序生产 | 云端 worker（受并行度上限约束） |
| 主编评审 Agent | rubric 十维自评，产出逐段修改指令 | 云端 worker |

**模型调用全部走云端模型配置**（任务级主备、密钥加密、预算硬停）——教师零密钥（ADR-02）。

### 2.1 云端 Agent 技术栈（ADR-05）

ADR-02 把编排搬到云端后，**云端必须自己提供一个能运行的 agent**：能分析任务、自主多轮调用 skill/tool、产出可校验的 spec——而不是一次 LLM 调用。

#### 2.1.1 能力清单（从需求倒推）

| 需求（来源） | 对 agent 运行时的要求 |
|---|---|
| 九步固定顺序、跑错序被挡（B3 验收） | 编排由**确定性状态机**掌控，agent 只在本步内决策 |
| 每节一个并行子代理（B3） | 并行 agent + 子代理委派 |
| 门禁①方案三动作、门禁②评审 reject（B2/B3） | **人机协同中断与恢复**（HITL interrupt → 教师裁决 → resume） |
| 崩溃恢复、断点续跑（非功能） | agent 会话可持久化、可 resume |
| 工艺包热迭代（ADR-02） | skill 载体（目录 + 模型可见的 skill 加载） |
| 21 个 `cloud_*` 类确定性工具（trend-studio 已在用） | 工具注册 + 确定性执行 + 结果回填 |
| 成本与溯源（非功能） | token 计量 + 预算硬停 + 逐产物溯源 |
| 多厂商模型 + 任务级主备（ADR-03 / 07 §9） | **provider-neutral** 模型接口 + 我们自己的路由与记账 |

#### 2.1.2 设计参照：SquadSight（`deepagents + assistant-ui`，Python 版）与 TS 版对等性核实

同门项目 SquadSight 已上线运行同一类需求（对话助手 + Runner 任务 + 子代理 + 技能），并已**从「Claude Agent SDK（CLI 子进程 + 手写 SSE）」整体迁移到 deepagents（Python 版）**。其已验证的接线方式是我们工艺组织的直接参照；TS 版对等性见 §2.1.3 开头的核实结论。

| 层 | SquadSight 实测做法 | 对我们的复用 |
|---|---|---|
| Agent 框架 | `deepagents>=0.7.8`（Python，LangChain/LangGraph 1.x 之上的深度代理层） | `create_deep_agent(model, tools, system_prompt, middleware, subagents, skills, backend, permissions, interrupt_on, checkpointer)` 一键组装 |
| 模型工厂 | `build_langchain_model()`：按 `protocol` 分支（anthropic `/v1/messages` / openai `/chat/completions`）；`sys_llm_models` 表（provider/protocol/api_key_encrypted） | 与我们 07 §9.1 的协议适配与 `ai_models` 加密列**同构** |
| 工具 | `tools.yaml`(JSON Schema) → `StructuredTool`；每次调用独立 `AsyncSessionLocal` + commit/rollback；错误返回 `{"error":...}` 不中断循环；`InjectedState` 注入图 state；参数宽容归一（Postel 法则） | 我们的确定性工具照此适配 |
| 技能 | `prompts/skills/<name>/SKILL.md`（YAML frontmatter + Markdown）→ `CompositeBackend(default=StateBackend, routes={"/skills/": FilesystemBackend(root_dir, virtual_mode=True)})` + `FilesystemPermission(write deny)` → **渐进披露**（agent 按需 `read_file`） | 对应我们 ADR-02 的"服务端版本化工艺配置"，且与 dsh 的 SKILL.md 同源 |
| 子代理 | `prompts/agents/*.md` frontmatter(tools/skills) 声明式 → `load_subagents()`，与主 agent 共用工具集 | 对应"逐节子代理 ×N" |
| HITL | `interrupt_on={ASK_USER_QUESTION_TOOL: {"allowed_decisions": ["respond"]}}`：模型调用该工具即**中断等待人工点选**，回答经 `respond` 合成 ToolMessage 回填 | **正好对应门禁①（三动作）与门禁②（reject）的中断-裁决-恢复** |
| 持久化 | `langgraph-checkpoint-postgres>=3.1.2`（`AsyncPostgresSaver`，thread_id 兼作 session_id） | 与"我们的 DB 为权威"目标一致 |
| 事件流 | `astream(stream_mode=["messages","updates","custom"], subgraphs=True)` → 转成 langgraph-sdk 兼容 SSE 帧（`messages\|ns` / `updates\|ns` / `custom` / `end` / `error`） | 前端 assistant-ui 直接可用（§2.2） |
| 前端 | `@assistant-ui/react` + `@assistant-ui/react-langgraph` + `@langchain/langgraph-sdk`；`useLangGraphRuntime`；组件 Thread/Message/Reasoning/ToolCall/Composer | 我们的对话 UI 统一栈（§2.2） |

**反面经验（SquadSight 已踩过）**：CLI 子进程 + stdio MCP + 手写 SSE + 用"输出长度推断进度"——已整体弃用，进度改为工具调用映射（确定性）。

#### 2.1.3 决策：deepagents（npm TS 版，进程内）+ 我们的确定性状态机（ADR-05 定案）

**核实结论（Context7 + npm）**：deepagents 有官方 TypeScript 实现（npm `deepagents`，当前 `1.16.4`，MIT，`langchain-ai/deepagentsjs`），**与 Python 版功能对等**——`createDeepAgent({ model, tools, systemPrompt, middleware, subagents, skills, backend, interruptOn, checkpointer, permissions, memory, ... })`，其中：

- `model` 接受 **`BaseLanguageModel` 实例**（任意自定义 `BaseChatModel` 可传入）→ 我们的 provider adapter 原生接入；
- `interruptOn` 逐工具 HITL（approve/edit/reject），恢复用 `new Command({ resume: { decisions } })`，**恢复状态按 checkpointer + thread_id 键控、与 agent 实例无关**（测试源码验证：中断后的全新 agent 实例共享 checkpointer 即可续跑）；
- skills 渐进披露与 Python 版同构：SKILL.md 发现（YAML frontmatter）→ 系统提示只注入名称+描述 → 模型按需 `read_file` 加载 → 工具按披露门控；
- `CompositeBackend` / `FilesystemBackend` / `StateBackend` 同名同义；
- checkpointer 兼容 LangGraph.js 生态（`@langchain/langgraph-checkpoint-postgres@1.1.2`，MIT）；
- peer：`@langchain/langgraph ^1.6.1`、`@langchain/core ^1.3.7`、`langchain ^1.6.4`。

| 层 | 选型 | 理由 |
|---|---|---|
| 编排层 | **我们的确定性九步状态机**（Fastify 同进程，DB 队列 + step 级 checkpoint + 三层校验 + 回灌 + 门禁） | 顺序纪律是需求写死的；崩溃恢复不依赖框架私有状态 |
| 步内 agent 执行面 | **deepagents（npm TS 版）进程内组装**：`createDeepAgent({ model, tools, subagents, skills, backend, interruptOn, checkpointer })` | 与 Python 版能力对等（已核实），**云端保持 TS 单栈**——不需要 Python 子服务、不引入第二套部署与测试 |
| 模型通道 | **我们的 provider adapter 实现为 `BaseChatModel` 子类**（openai/anthropic/minimax 三协议，密钥自 `ai_models` 解密；内部做任务级主备、冷却、token 计量、`ai_usage_events` 记账、预算硬停） | 框架只管流程，**模型路由与成本必须在我们手里**（07 §9/§10） |
| 工具层 | **我们的确定性工具集**（检索 units / 取行情 / 读术语与案例股 / 写草稿产物），注册为 LangChain tools；错误返回 `{"error":...}` 不中断循环；参数宽容归一（Postel） | 工具即云端服务能力（05 §3、06 §5）；SquadSight 的 adapter 纪律直接继承 |
| 工艺(skill)层 | `skills/<name>/SKILL.md`（frontmatter）+ `CompositeBackend` 只读路由（`/skills/` → FilesystemBackend）+ 写权限 deny + 渐进披露；版本随产物记 `skillVersions` | 与 dsh 的 SKILL.md 形态同源；与 ADR-02 的服务端版本化工艺配置一致 |
| 人机协同 | `interruptOn`（门禁①②的中断点）→ 状态机挂起 + 工作台审批 → `Command({ resume })` 续跑同 thread | 门禁是我们自己的业务语义；HITL 机制现成且按 thread_id 键控，适配 worker 轮换 |
| 持久化 | **我们的 PG 为权威**（`production_tasks` step checkpoint）；agent 会话由 `@langchain/langgraph-checkpoint-postgres` 承载，`thread_id = (courseId, sectionId, step)` 关联 | 崩溃恢复不依赖框架私有状态；会话历史可审计、可级联清理 |

**进程内集成（无子服务契约）**：deepagents 与状态机同进程——状态机按 step 直接 `invoke`/`stream` deepagents 图（传 `config.configurable.thread_id`），产物候选 spec + 依据（citations/assertions）由 TS 引擎做确定性校验（不由模型裁决）；失败/取消按稳定 code 映射到重试/回灌/待办（对齐 §3.8）。

**备选**（若 Spike 发现 TS 版能力缺口）：Python deepagents 子服务（SquadSight 同栈，§2.1.2 的接线方式直接复用）——切换只影响步内执行面的部署形态，不动状态机、契约与 UI。

#### 2.1.4 步内 agent 形态（回应"必须能智能分析任务、调用 skill/tool"）

每个角色的一步不是一次 LLM 调用，而是一个**有界 agent 运行**：

```
步骤开始（状态机给出目标、输入、可用工具清单、必守断言）
  → 规划：产出本步子任务（可先调 skill 工具加载对应工艺）
  → 执行：自主多轮「模型 → 工具 → 结果回填 → 模型」，直到产出候选 spec
  → 自检：模型自述依据（citations / assertions）
  → 确定性校验（schema → 语义 → 教学质量）——由我们的引擎执行，不由模型裁决
  → 通过则落产物并推进状态机；失败则回灌（≤3 次）或转人工待办
```

- **智能分析任务**：规划段 + 可用工具承担（先查 source units / 术语表 / 案例股清单再动笔），不是把输入全塞进一次提示词。
- **skill**：模型按需调用 skill 工具加载工艺（如"分节写作工艺"），加载记录进溯源的 `skillVersions`。
- **终止条件**：由状态机给出（"产出满足断言的 spec"或"本轮预算耗尽"），agent 不得自行决定跳过步骤。

#### 2.1.5 前置验证（Spike，开发启动前必须跑完）

| # | 验证项 | 判据 |
|---|---|---|
| S1 | **deepagents（TS）能力核实**（Context7，已初步完成） | `createDeepAgent` 全参数对等 Python 版（subagents/skills/backend/interruptOn/checkpointer）；`model` 接受自定义 `BaseChatModel`；版本 `1.16.4`、MIT、peer `@langchain/langgraph ^1.6.1` |
| S2 | **进程内集成**：状态机按 step `invoke`/`stream` deepagents 图（`config.configurable.thread_id`） | 作业/run 状态/事件流/取消语义对齐；并发认领下不丢状态 |
| S3 | **checkpointer 与我们的表对齐**（`@langchain/langgraph-checkpoint-postgres@1.1.2` + `production_tasks` step checkpoint） | `thread_id=(courseId,sectionId,step)` 关联；worker 崩溃后新实例共享 checkpointer 即可 `Command({resume})` 续跑；不重复应用 |

### 2.2 前端对话 UI 适配（assistant-ui）

对话类界面（教师工作台的生产看板对话/评审卡/待办、学员端问答）统一用 **assistant-ui**，与后端框架解耦：

| 端 | 适配方式 |
|---|---|
| 教师工作台（浏览器，云端 React） | 后端把 deepagents 的 `astream` 输出转成 **langgraph-sdk 兼容 SSE 帧**（`messages\|ns` / `updates\|ns` / `custom` / `end` / `error`，同 SquadSight），前端 `@assistant-ui/react-langgraph` 的 `useLangGraphRuntime` 直接可用；审批卡/决策卡用自定义 tool UI 渲染（HITL 点选） |
| 学员端（DSH 插件 Browser 半 React） | 用 assistant-ui 组件渲染问答/引用/工具卡；runtime 走**自研 DSH Remote adapter**（plugin host ↔ browser 半），不直连云端 SSE（学员端问答在云端，但消息面经 DSH Remote 协议） |

- 组件基线：`ThreadPrimitive` / `MessagePrimitive`（content part 分流：Text=Markdown、Reasoning=折叠思考块、ToolCall=状态卡）+ `Composer`；引用片段用自定义 content part 渲染为可点 chips。
- 门禁①②的"三动作/评审卡"用 assistant-ui 的 **HITL interrupt UI**（用户点选后 `respond` 回填），不用自绘按钮组。

## 3. 阶段一：媒体与素材管线

### 3.1 直传上传（需求 B2）

| 项 | 规则 |
|---|---|
| 建素材 | `POST /v1/admin/content/media-assets` → 返回 `assetId` 与直传凭据 |
| 凭据 | HMAC 签名，绑定 `assetId + 字节数 + sha256 + 有效期`；服务端只验签不中转字节 |
| 上传 | 浏览器 `PUT` 字节到存储直传地址；**不经业务进程内存** |
| 限值 | 单文件 ≤ 2GiB；Content-Type 仅 `application/octet-stream`；超限 `413`、类型不符 `415` |
| 摘要 | 可选 `x-file-sha256`（64 位小写 hex）；流式计算，不符 `400` 并删除半成品 |
| 状态 | `awaiting_upload → uploaded`；重复上传覆盖旧源并重置转写/生成 |
| 音轨校验 | 必须同时存在视频流与音频流，否则拒绝并清理半成品 |
| 体验 | 进度可见、可重试 |

服务端路由级 `bodyLimit = 2GiB`；`preParsing` 先完成会话鉴权与限流再消费 body。

### 3.2 存储布局与抽象

```text
workspace/pipeline/            # 容器内挂载为 /data
  storage/                     # MEDIA_STORAGE_DIR
    sources/<assetId>/source   # 原始上传字节（只读）
    work/<assetId>/{audio.wav, chunks/, hls/, keyframes/}
  hls/                         # PIPELINE_HLS_DIR（与 storage 同卷）
    hls/<assetId>/{index.m3u8, seg_00000.ts}
  figures/                     # FIGURE_DIR：figures/<figureId>/<candidateId>.jpg
```

- **`MediaStore` 接口**：建目录、流式写、SHA-256、原子 rename、清理、HLS 校验；实现两种：本地文件系统（`MEDIA_STORAGE=local`）与对象存储（S3 兼容 + SigV4 预签名，`MEDIA_STORAGE=cos`）。
- **同卷约束**：`PIPELINE_HLS_DIR` 解析后必须与 `MEDIA_LOCAL_DIR` 相等，否则启动失败；HLS 从 `work/<assetId>/hls` **原子 rename** 到 `hls/<assetId>`，跨卷直接失败，不做复制降级。
- **签名范围隔离**：`media_assets.hls_path = 'hls/<assetId>/index.m3u8'`，播放签名前缀只覆盖该目录，**源文件永不进入签名范围**；图示按单文件签发，不能靠换 figureId 越权读取。
- 对象存储模式下对象键与 `hls_path` 一一对应；桶保持私有读，只有应用签发的预签名地址可访问。

### 3.3 媒体校验（probe）

```
ffprobe -v error -print_format json -show_format -show_streams
```

| 检查 | 失败 |
|---|---|
| 存在视频流 **且** 存在音频流 | `422`（终态失败） |
| 时长 > 0 且 ≤ `PIPELINE_MAX_SOURCE_SECONDS`（默认 14400s = 4h） | `422` |
| 媒体损坏/无法解析 | `422`，仅返回稳定 `error_code` |

### 3.4 转码与抽帧（ffmpeg）

固定参数模板（**只 `spawn(FFMPEG_PATH, args)`，禁止 shell**；启动探活 `-version` 5s，缺失即启动失败）：

```bash
# HLS：单码率 H.264/AAC，6s 分片，VOD
ffmpeg -y -i source \
  -c:v libx264 -preset veryfast -crf 23 -pix_fmt yuv420p -vf "scale='min(1280,iw)':-2" \
  -c:a aac -b:a 128k -ar 48000 \
  -f hls -hls_time 6 -hls_playlist_type vod -hls_segment_filename 'seg_%05d.ts' \
  -progress pipe:1 index.m3u8

# 16kHz 单声道 PCM16（供 ASR）
ffmpeg -y -i source -vn -ac 1 -ar 16000 -c:a pcm_s16le audio.wav

# 静音检测（只读 stderr）
ffmpeg -y -i audio.wav -af silencedetect=noise=-30dB:d=0.5 -f null -

# 切块
ffmpeg -y -ss <start> -t <duration> -i audio.wav -c:a pcm_s16le chunk.wav

# 关键帧：按图示计划时间点抽单帧，最长边 ≤1600
ffmpeg -y -ss <sec> -i source -frames:v 1 -vf "scale='min(1600,iw)':-2" -q:v 2 keyframes/<sec>.jpg
```

- 进度：解析 `-progress pipe:1` 的 `out_time_ms`；超时 `PIPELINE_FFMPEG_TIMEOUT_MS` / `PIPELINE_AUDIO_TIMEOUT_MS`；取消时 `SIGKILL` 子进程并清理工作区；stderr 只进内部日志，不回客户端。
- 发布前校验：playlist 存在 `#EXT-X-ENDLIST`、全部分片存在且非空，再原子 rename 到 HLS 目录。

### 3.5 ASR 转写

| 步骤 | 规则 |
|---|---|
| 切点 | 静音检测（-30dB / 0.5s）得到切点，按 ≤480s 切块 |
| 并发 | 最多 `PIPELINE_ASR_CONCURRENCY`（默认 2）并发；每块**独立缓存**，重跑直接复用（避免重复计费） |
| 调用 | 平台 ASR（模型配置页维护）：multipart `file=chunk.wav` + `model` + `response_format=verbose_json` + `timestamp_level=sentence`；解析器兼容 `sentences/segments/utterances` 与多种时间键 |
| 重试 | 每块最多 3 次（429/5xx/网络），退避后仍失败则该块 `failed`（终态，任务失败不吞） |
| 兜底 | 无时间戳时退化为「整块一句话」，并在元数据标 `timestamp_fallback` |
| 拼接 | 全部块完成后**单事务**拼接：块内局部毫秒 + 块起点 → 全局时间戳；丢弃空白/重叠；按 ≤30s 分组写 `transcript_segments`；时间戳必须单调不重叠 |
| 隐私 | 转写正文只存 DB；仅管理端接口可取；日志与指标不记正文 |

**增量可见**：每转完一块即落可读段落（`partial=true`），工作台可读、理解与生产提前起跑（需求 B2 验收项）。

### 3.6 关键帧与帧轨道

- 采样：ingest 时**场景检测 + 1 帧/15s** 采样，去重后存 `work/<assetId>/keyframes/`；云端只抽帧，**不做视觉理解**（理解在 §4）。
- 补帧：图示计划（`sourceHint` 时间点）需要时按时间点单帧抽取，最长边 ≤1600；`sec` 必须落在所引 source unit 时间范围内（复检 `sec_not_grounded`）。
- 质量门：抽帧结果校验**非纯色/非黑屏**（方差与亮度阈值），不合格直接丢弃并降级为 `generated` 图示。
- 访问：`GET /v1/admin/content/media-assets/{assetId}/frames?from&to` 返回**短时签名帧 URL**（供生产端 VLM 消费）。

### 3.7 ingest 任务编排

- 阶段序列：`probe → transcode → transcribe → finalize → done`；队列与 worker 状态机见 [02 云端服务架构](02云端服务架构.md) §4。
- 幂等：已探测时长复用；已提升的合法 HLS 跳过转码；成功转写块复用；产物一次性写；重复 ingest 返回原状态。
- 取消：queued 立即取消；running 置 `cancel_requested`，worker 在阶段边界检查并中止 fetch / `SIGKILL` ffmpeg；已产生的块缓存保留供重试。

### 3.8 管线错误映射

| 状态 | 场景 |
|---|---|
| `400` | 参数/ID 非法；SHA 不符 |
| `401/403` | 未登录；角色不足或设备不匹配 |
| `404` | 素材/任务不存在 |
| `409` | 状态不允许（重复 ingest、素材已有产物） |
| `413/415` | 上传超限；Content-Type 非 octet-stream |
| `422` | 媒体无音轨 / 超时长 / 损坏；源文件缺失 |
| `429` | 管线接口限流 |
| `503` | 管线未启用、ffmpeg 不可用、ASR/模型未配置 |

客户端只见稳定 `error_code`（≤64 字符）与静态文案，内部 stderr 不外泄。

## 4. 阶段二：多模态理解

- 输入：转写分组（5–10 分钟 chunk）+ 该 chunk 时间窗内的采样帧。
- 输出 source unit：`{时间范围, 转写, 画面描述, 图表类型, 讲解要点, 关键帧引用}`。
- 幂等：`(asset_id, start_ms)` 唯一；重跑按缺失 chunk 补齐，不重算已有。
- 帧描述质量纳入 rubric 评估集（描述失真算 grounded 失败）。

## 5. 阶段三：课程综合（门禁①之前）

| 步骤 | 规则 |
|---|---|
| 目录先验 | 以人工目录（篇→卷→课时）为骨架；**不允许发明目录**（目录外章节不创建） |
| 概念归一 | 跨课时抽取概念 → 聚类合并 → `concepts`（含别名）+ `concept_edges`（`prerequisite` 标注教学依赖序） |
| 术语表 | `concepts.name` 为正文与课件 spec 的术语校验基准；未收录术语在第 2 层校验被拒 |
| 匹配度 | 某节证据不足（匹配度低于阈值）→ 该节标红并给匹配度，教师裁决「修订提纲」或「补充素材」，**其余节不受影响** |

### 门禁①：方案确认（工作台审批组件，三动作）

| 动作 | 语义 |
|---|---|
| 批准 | 方案锁定为基准版，解锁逐节生产 |
| 微调 | 直接结构化编辑方案条目（章节增删合并 / 改名 / 概念别名 / 分节粒度），即时生效 |
| 打回 | 给自然语言修改指令 → 综合 Agent 基于**已有 source units** 重起草（不重跑素材理解，秒级返回新草案） |

方案草案与人工修改留版本轨迹（v1 → v2 …）；确认后锁定，中途变更走「追加素材 B 重做骨架」。

## 6. 阶段四：逐节生产（九步固定顺序）

引擎**强制顺序**，跑错序被挡并提示当前步：

| # | 步骤 | 产出 / 约束 |
|---|---|---|
| 1 | 案例股 | 本节案例股清单（代码/窗口/事件锚点），云端复检 |
| 2 | 行情同步 | 按节声明周期拉取行情缓存（幂等 upsert），未就绪显式占位 |
| 3 | 行情读回 | 读回确认（口径/交易日/窗口），失败降级为占位，**不伪造数据** |
| 4 | 图示 | 三路分工（§8），配额：keyframe ≤6/节、diagram ≤2/节 |
| 5 | 回放课件 | 逐根回放 spec（`bar-replay-decision`），断言必须可证明（06 文档） |
| 6 | 正文 | grounded 写作（Markdown + DSL），1200–3000 字；事实段带 `[[unit:]]` 锚 |
| 7 | 其余课件 | mcq-quiz / pattern-quiz / flashcards / checklist / timeline-explorer / calc-trainer 等 |
| 8 | 评审 | rubric 十维自评 → approve / reject + 逐段修改指令 |
| 9 | 溯源 | 上报 `(taskKey, model, tokens, skillVersions, targetId, latencyMs)` 入用量账本 |

- 并行：逐节子代理并行，**单课并行度上限可配**（起步 3–4 节），单课生产不阻塞其他课。
- 断点续跑：checkpoint 落 DB（按 step），worker 崩溃恢复不依赖本地状态。
- 章节正文结构（`chapter-authoring` 工艺固化）：概念 → 判断依据 → 实例 → 检查清单 → 常见误用。

## 7. 三层校验与收敛

| 层 | 位置 | 内容 | 失败处理 |
|---|---|---|---|
| 1 schema | worker 工具边界 + 云端复检 | zod：字段/长度/枚举/引用存在性 | 回灌重写 |
| 2 语义 | worker + 云端复检 | 断言证明（06 文档）、答案唯一性、术语 ∈ concepts、citations 可回溯、`figure:`/`:::` 引用存在、片段窗合法、案例股口径 | 回灌重写；≤3 次不过 → 人工待办 |
| 3 教学质量 | 主编 Agent | rubric 十维评分（grounded 含「行情数值可核」一票否决）、阈值可配 | reject 回灌整节重写 |

- **收敛规则**：回灌 ≤3 次，每次带回具体失败原因；超限转**人工待办**（工作台可见，绝不静默丢弃）。
- **绝不部分落库**：任一校验失败，整节产物不落库或整体回滚。

## 8. 图示三路

| 路 | 生成方式 | 教学承载 | 配额 |
|---|---|---|---|
| `diagram` | 模型出**结构化 spec**，服务端确定性渲染 SVG | 承载教学信息（标注文字 100% 正确） | ≤2/节，模板白名单 |
| `keyframe` | 按 source unit 时间戳取原始画面 | 承载讲师原始画面 | ≤6/节 |
| `generated` | 文生图（平台模型） | **仅装饰，禁止承载教学信息** | 每章 ≤3（课级 ≤24） |

- 禁止生成写实 K 线、收益曲线、行情截图或带品牌标识的假界面；提示词由服务端模板拼装，模型不得改写 `kind`、数量与安全约束。
- 图示下载后校验 JPEG/PNG、单张 ≤8MiB、边缘 ≥800px，再压缩落 `figures/<figureId>/<candidateId>.jpg`；记录 `prompt/model/seed`，用量记 `ai_usage_events.images`。

## 9. 人工待办与异常契约

| 异常 | 处理 |
|---|---|
| 提纲与素材不匹配 | 该节标红 + 匹配度；教师裁决修订提纲或补充素材；其余节不受影响 |
| 课件证据不足 | 子代理**挂起**该节（状态显式、进度保留）；补素材入库后**自动恢复**，不重跑已完成步骤 |
| 校验/自评失败 | 回灌 ≤3 次；超限转人工待办 |
| 概念归一冲突 | 转人工待办，教师裁决后继续 |

共同纪律：异常在看板可见；恢复动作幂等（重复触发不重复重置）；不产生部分落库。

## 10. 追加素材三选一

| 选项 | 语义 |
|---|---|
| A 只补这节 | 仅重跑受影响节的对应步骤 |
| B 重做课程骨架 | 重跑综合阶段，受影响节步骤重置 |
| C 只入库暂不生产 | 素材入库存档，不触发生产 |

工作台**先只读展示影响面**（哪些节会被重评）再让教师确认；决策持久化；受影响节生产步骤重置，**回灌预算保留**。

## 12. 门禁、签批与内容指纹

### 五道发布门禁（一份实现）

发布就绪度与发布读**同一批检查结果**：

| 门禁 | 判定 |
|---|---|
| 图示解析 | 正文 `figure:` / `:::figure` 引用均可解析且候选就绪（`figure_unresolved`） |
| 课件断言 | 每个课件断言有证明记录（`widget_unproven`，附 widgetIds） |
| 片段窗 | 片段窗合法且落在已发布正文 clip 窗内（`clip_invalid`） |
| 标注与回放 | 标注引用有效（`annotation_unresolved`）、回放课件已证明（`replay_unproven`） |
| 终审签批 | 审批记录存在且指纹一致（`approval_required` / `approval_stale`） |

### 内容指纹

签批 = 对课程**内容指纹**签名，发布 = 重算指纹比对。覆盖：章节教材、节教材（dslVersion + markdown + citations 排序去重）、课件（id/type/specVersion/spec/assertions）、图示（id/kind/caption/assetId/sourceSec/spec）、节级案例股清单、片段（id/title/起止秒/text）。

- **改内容即已签批失效** → `approval_stale`，需重新签批（需求 B4）。
- 顺序：内容完整性问题先于签名问题报错（前者可直接定位修）。
