# 04 学员端插件架构

版本：v1.0（2026-11-12）
关联：[01 整体架构](01整体架构设计.md) · [06 教材呈现与交互课件](06教材呈现与交互课件实现方案.md) · [07 平台服务方案](07平台服务方案.md)

> 本文回答「学员端插件由哪些部分组成、与 DSH 宿主如何协作、边界在哪」。
> 继承说明：结构形态与平台硬约束继承 trend-studio `apps/coach`（已实测验证）；**推理位置**按 ADR-03 反转为云端。

---

## 1. 定位

学员端 = **DeepSeek Harness 框架 + trend-coach 插件**。框架负责宿主能力（会话、模型、凭据、右栏、composer 扩展、附件），插件负责学习域能力（课程检索与问答、引用回跳、课程页渲染、播放、即时提问）。

铁律：**插件不存内容、不做检索、不做鉴权、不做推理**——四件事全在云端。插件是「带上下文的对话与渲染壳」。

## 2. 结构：host / client / shared 三分

| 半 | 运行环境 | 职责 | 纪律 |
|---|---|---|---|
| `src/host/` | Node | 插件入口装配、设备码授权与令牌刷新、云端客户端（契约版本校验）、工具注册（检索/目录/播放）、不可信文本边界包裹、错误映射 | 入口保持薄；边界校验只在 host 做一次，client 不重复实现 |
| `src/client/` | 浏览器（DSH Browser 半） | 侧栏面板、播放器、课程页装配、选中提问、语音采集与转写插入 | 纯函数拆分（装配/校验/渲染分离）便于单测；不引入 Node API |
| `src/shared/` | 两半共用 | 领域类型与上限常量 | 禁 Node 专属代码（会进 client bundle） |

## 3. 与宿主的协作面

| 能力 | 机制 | 用途 |
|---|---|---|
| 工具注册 | `ctx.tools.register` | 课程检索、目录、播放会话、问答提交 |
| 右栏面板 | `ctx.sidebarRightTabs.register` + keyed slot | 「趋势伴学」面板（播放器 / 片段 / 笔记） |
| composer 扩展 | 会话作用域 slot `conversation.input.right` + `captureInsertion` / `insertText` | 语音提问按钮与转写文本插入 |
| 临时提示段 | `ctx.systemPrompt.section()` | 学习上下文注入（**不进聊天历史**，每次组装求值） |
| 附件 | `@deepseek-ai/dsh-attachment` | 图片提问附件 |
| 凭据 | record（`<scope>/<id>`）+ ref | 设备令牌只存本机凭据库 |

平台硬约束（编号沿用 trend-studio dsh 基线 P1–P12，仅约束本插件）：Remote 注入顺序（P1，先 `$mount()` 再 `ctx.inject`）、右栏 tab 形状（P2）、Markdown 链接只渲染 http(s)（P3，故引用走 `segmentId` 主路径）、peer 精确同版（P5）、凭据库权限（P8）、授权流生命周期（P9）。

### 3.1 如何使用 dsh 的模型（不在插件里另配模型）

**原则：模型与密钥由宿主持有，插件只提供能力与上下文。** 三条正规路径：

| 路径 | 机制 | 用途 |
|---|---|---|
| ① 工具路径（主流） | `ctx.tools.register` 注册工具 → **宿主 agent loop 用会话当前模型**决定调用哪个工具 → 工具返回值进对话 | 检索、目录、播放会话、问答提交等一切"给模型能力"的动作 |
| ② 提示段路径 | `ctx.systemPrompt.section()` 注入上下文（每次组装求值，**不进聊天历史**） | 把学习上下文（当前课程/节/播放位置）喂给宿主模型 |
| ③ 工艺/技能路径 | `ctx.skills` + patch `customSkillDirs` 挂 SKILL.md 工艺包 | 把"该怎么回答"的工艺交给宿主模型 |

三条路径都不碰密钥：模型由用户在 dsh 会话/设置里选定，密钥只存在 dsh 凭据服务（`llm-pi-ai` provider 条目的 `apiKeyEnv` 指向凭据 ref）。

**不推荐的路**：插件自己拿 key 调模型。唯一可行姿势是经**凭据服务 ref** 解析（`ctx.get('credentials').resolve(credentialRef(ref))`，profile 里只存引用名，取不到再退进程环境），但这等于把密钥流经插件，与 P8（凭据库权限收紧 600，否则整体失效且只在启动时报）叠加后风险很高。

**trend-suite 的口径**：ADR-03 之后学员端**问答推理在云端**，插件不持有任何模型密钥、不做推理；宿主模型在学员端仅服务于 dsh 自身的对话场景，与课程问答链路无关。云端的模型调用见 [07 平台服务方案](07平台服务方案.md) §9。

### 3.2 鉴权：插件与云端之间怎么做身份

三层，各自独立：

| 层 | 机制 |
|---|---|
| 插件 ↔ 宿主 | **不是 HTTP 鉴权**：靠"能力面授予"——`export const inject = ['tools', 'credentials']` 声明依赖的宿主服务，宿主按面授权；凭据由 P8 的权限规则约束 |
| 插件 ↔ 云端（学员端） | **设备码授权**：客户端申请 device code（人工核对 userCode）→ 浏览器授权页批准 → 换 grant（accessToken/refreshToken/expiresAt/deviceId）→ grant 存 dsh 凭据库 record（`credentialKey('<plugin>', 'device')`，kind=`grant`） |
| 请求约定 | 每次带 `authorization: Bearer <accessToken>` + `x-device-id: <deviceId>`；**提前 30s 刷新**；登出 = `POST /v1/auth/revoke` + 删除本地 record（吊销尽力而为，不因网络失败中断本地登出） |

**错误语义（必须按此实现，勿自造）**：

| 云端返回 | 插件行为 |
|---|---|
| `401` | 用 refreshToken 轮换**一次**后重试；仍失败 → `AUTH_EXPIRED`（提示重新设备授权） |
| `403` | `DEVICE_MISMATCH`（设备与令牌不匹配）→ **不重试**，提示重新登录 |
| 错误体 | 形如 `{ error: { code, message } }`；插件只认字符串 `code`，其余一律当无码 |

教师端（trend-suite）走浏览器 Web 会话，不走设备码：token 只存 `sessionStorage`、不落 Cookie、无凭据托管面（见 02 文档 §3）。

## 4. 关键链路

### 4.1 课程问答（ADR-03：推理在云端）

```
学员输入 → 插件组装（问题 + 本机学习上下文）→ 云端 /v1/billing 额度预检
        → 云端混合检索（词法+向量，仅已发布内容）
        → 云端平台模型生成（只引检索片段，不自造时间点）→ 云端审核过滤
        → 额度扣减（幂等）→ 返回 {答案, 引用片段[], 消耗}
        → 插件渲染（引用芯片可点）→ 点击引用 → 请求按节播放会话 → 右栏播放器 seek
```

- 插件端**不持有模型密钥**（ADR-03 后无 BYOK 通道）；模型由云端按任务路由与主备选择。
- 额度耗尽：云端返回明确错误码（非静默失败），插件展示充值入口；**检索与课程浏览不受影响**。
- 空召回：云端返回「课程未覆盖 + 最近知识点（≤5，仅标题）」，插件如实呈现，禁止编造。

### 4.2 引用点击 → 播放定位

- 引用为 `segmentId`（稳定主键）+ 可读编号芯片；点击后插件调云端 `POST /v1/catalog/sections/{id}/playback` 取得**按节签发**的播放会话。
- 会话窗口须完整落在该节已发布正文的 clip 窗内（越窗 `409 playback_window_invalid`）。
- 播放器按 `from` 起播、到 `to` 自动暂停（30–60s），水印已叠加，播放免费不耗额度。

### 4.3 学习场景上下文（S6）

- 插件维护本机全局学习上下文（当前课程/节/播放位置/最近选中），由 `systemPrompt.section()` 每次求值注入。
- 默认开启、可关；**只在本机内存**，不进云端、不进指标、不随会话历史落库。
- 选中即问：浏览器全局选中检测 → 悬浮「提问」→ 文本带上下文入 composer。
- 语音提问：≤60s，浏览器采集 → 云端 ASR → 文本插入输入框**待确认**；**转写计入额度**；音频仅内存流转，不落盘不进日志。

### 4.4 课程页装配

- 目录 + 逐节详情在客户端装配成共享视图（纯函数 `assembleCourseView`），节详情并发拉取、单节失败不阻断整页；服务端不做课程级聚合端点。
- 渲染组件与管理台预览**同源**（共享渲染包），预览即学员渲染路径。
- 图示签名地址随节详情下发，客户端按 `figureId` 汇总映射，页面会话内复用不逐块重取。

## 5. 边界与错误

| 情形 | 插件行为 |
|---|---|
| 云端契约版本不匹配 | 提示升级客户端，**不静默降级** |
| 网络/超时 | 展示可重试文案，保留用户输入 |
| 额度不足 | 明确错误 + 充值入口；浏览播放继续可用 |
| 内容未发布 | 如实提示「本课程暂无可读的已发布节」 |
| 引用片段失效 | 提示该片段已不可用（内容变更），不跳空白播放器 |

## 6. 隐私护栏

- 学习上下文、语音音频与转写结果只在本机内存；转写文本经用户确认后才提交云端。
- 学员作答（如逐根回放判断、互动题目选择）**只在本机**：不落库、不进校验记录、不进指标事件、不随溯源上报；云端只保存**正确答案的程序证明**。
- 指标上报默认关闭、可撤回；学习上下文永不进指标。

## 7. 性能与可用性

| 项 | 目标 | 手段 |
|---|---|---|
| 问答首 token | P95 ≤ 3s（平台模型） | 流式返回 + 骨架屏 |
| 检索 | P95 ≤ 300ms | 混合召回 + 结果缓存 |
| 起播 | ≤ 2s | 预签名 + HLS Range |
| 教材正文 | P95 ≤ 1.5s | 节详情缓存 + 增量装配 |
| 语音端到端 | P95 ≤ 5s | 边录边传 / 分片上传 |
| 离线 | 只读已缓存节（进行中） | 明确降级提示 |

## 8. DSH 平台硬约束基线（P1–P12）

以下为 trend-studio 实测得出的 dsh 宿主约束，**trend-suite 学员端插件继承全部编号**（ADR-02 后仅约束学员端）。新需求先对照本表再定方案；两插件 PRD 与实现以 `P<n>` 引用。

| # | 约束 | 内容 |
|---|---|---|
| **P1** | Remote 注入顺序 | 第三方服务须先 `ctx.remote.$mount()`，成功后再 `ctx.inject(['remote.<ns>'], …)`；写进静态 `inject` 会死锁 |
| **P2** | 右栏 tab 形状 | `ctx.sidebarRightTabs.register()` 的 `guide` 必须是数组；tab body 注册在 keyed slot，key = tab `id` |
| **P3** | Markdown 链接 | dsh 只把 `http(s)`/`mailto` 渲染为可点 `<a>`，**自定义 scheme 降级为纯文本** → 引用交互走 `segmentId` 代码块主路径（+ 链接拦截备选） |
| **P4** | 视频定位 | 播放器服务端必须支持 **HTTP Range**，否则 seek 需下载整段 |
| **P5** | 版本与安装 | peer 与宿主**精确同版**（写范围会解析到旧依赖链 404）；`plugin add` 需 `-w`；插件包不携带 `@deepseek-ai` 运行时依赖（宿主提供） |
| **P6** | web-app 副作用 | `dsh-web-app` 在宿主层把 `skill-filesystem`/`tool-skill` 整行禁用；需技能包的 profile 必须 patch 显式置回 `disabled:false`，否则工艺包**静默**不加载 |
| **P7** | credentials 时序 | `dsh-credentials-local` 激活时序不保证；`credentials` 必须与 `tools` 一起写进静态 `inject` |
| **P8** | 凭据库权限 | 凭据服务拒绝加载「所有者之外可读」的凭据库（报 `MISSING_CREDENTIAL`，密钥/令牌整体失效且只在启动时报）；写 ref 后必须收紧 `600` |
| **P9** | 授权流生命周期 | 一次授权尝试只存活于发起进程（刷新即作废）；seam 无登出/吊销语义 |
| **P10** | rc 长任务稳定性 | rc 版 dsh 长任务稳定性待试点验证；触发条件（校验回灌无法稳定收敛）下重启选型，备选 DeepAgents |
| **P11** | Web UI 安全头 | 0.2.1-rc.5 实测文档响应无 CSP（浏览器可直连媒体域）；升级 dsh 必须复验 `img-src`，收紧则改由 Host 代理图片字节 |
| **P12** | headless 无界面 | headless 应用面没有命令分发与操作界面；产品要界面必须 `base + dsh-web-app`（并遵守 P6） |

**升级复验清单**（每次升 dsh 必跑）：CSP/安全头（P11）→ 自定义 scheme 行为（P3）→ slot/`InputActions` API → `systemPrompt.section` → attachment 行为 → web-app 与技能链路共存（P6）→ 凭据库权限语义（P8）。

## 9. 插件打包与装载

| 项 | 规则 |
|---|---|
| 打包形态 | npm tarball（`dsh plugin add <pkg> -w`）；包名不可改（插件 ID 依赖 `package.json` name） |
| 双半产物 | Host 半由 Node 直接编译；Browser 半用 esbuild 打包为单文件并以 `__ModuleLoader__` 包装注入 |
| 最小类型声明 | 仅声明用到的 dsh 客户端服务类型（`dsh.d.ts`），不整体引入 dsh 类型包，避免版本漂移 |
| 装配 | `cordis.patch.yml` 在 bundle patch 阶段注入插件与配置默认值 |
| 依赖纪律 | 插件包**不携带** `@deepseek-ai` 运行时依赖（宿主提供）；不得依赖管理台/门户私有运行时（渲染包同理，见 06 文档） |
