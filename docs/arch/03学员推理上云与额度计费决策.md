# 03 学员推理上云与额度计费决策（ADR）

日期：2026-11-11　状态：已采纳（学员端需求 v0.2 起生效）

## 决策

**学员问答推理改为平台供给**：云端完成「检索（RAG）+ 模型生成带引用回答」，学员端只做渲染与交互；**弃用 BYOK**（学员自带模型 Key 通道移除）。

**额度计费**：注册赠初始额度；每次智能问答消耗额度（余额透明）；**耗尽即停生成**并引导**充值缴费**续用。课程浏览、播放、进度等**内容消费不耗额度**——只有智能生成计费。

**学员端保留客户端形态**（一键安装包，内嵌运行时与插件）：推理虽上云，保留本地会话能力与未来本地扩展空间；安装成本由一键安装包与首启向导承担。

本决策**反转**三条前代口径：「云端不做推理」「平台不发兜底 Key（无 Key 学员不支持）」「本期不做支付」。

## 动因

1. **BYOK 是开通漏斗的最大流失点**：多数学员不会获取与配置模型 API Key——这是「填 Key」步骤的本质问题，不是向导写得不够好。
2. **BYOK 同时是客户端重形态的唯一硬理由**：推理上云后，客户端只剩渲染职责，但保留它换来本地会话与演进空间，且一键安装包已把安装成本压到一步。
3. **商业模式闭环**：平台供给 → 额度计量 → 充值续用，链路自洽；若保留 BYOK 免费通道会绕穿计费，故一并移除（未来若要高级通道再评估）。
4. **基础设施高度复用**：模型配置（加密 / 任务级主备 / 健康冷却）、混合检索、用量账本、按用户限流在云端全部现成；主要新增是配额账户与支付集成。

## 相邻决策

| 项 | 结论 |
|---|---|
| 推理服务 | 云端新增学员问答推理端点：检索 → 平台模型生成（带引用）；走既有模型路由与主备降级 |
| 额度体系 | 学员配额账户：注册赠额、按次（或按 token）扣减、耗尽拒绝生成；用量入账本（学员维度） |

| 防滥用 | 赠额防刷：注册门槛 + 账号 / 设备维度限流；策略待冻结 |

| 提示注入与内容边界 | 云端生成内容经不可信数据处理与输出过滤；「不荐股」红线不变 |

## 代价与风险

- **推理成本全额转移平台**：额度定价必须覆盖单位成本（按模型单价配置可估），需成本模型与调价机制。
- **内容责任上移**：从「学员模型的输出」变为「平台生成」，审核与合规责任加重（生成内容审核、备案、免责声明强化）。
- **支付系统为全新增量**：渠道集成、订单对账、退款争议。
- **赠额防刷**与刷额度攻击面新增。
- 语音即时提问的隐私口径不变（音频仅内存流转），但转写计入额度。

## 对流程的影响

学员开通从「三步」再收敛为**两步交互**：下载一键安装包 → 首启登录（**不再配置模型 Key**）→ 进入学习；新增「额度耗尽 → 充值」异常分支。详见 [学员端需求 v0.2](../requirement/学员端需求v0.2.md) 与 [流程图](../flow/student-e2e.html)。
