## 第一部分 · 额度计费与充值（ADR-03）

### 1. 计费边界（铁律）

| 行为 | 是否计费 |
|---|---|
| 智能问答（含其语音转写部分） | **计费**（按次） |
| 课程浏览 / 播放 / 进度上报 / 体系页 / 课件作答 | 免费 |
| 互动练习、逐根回放作答 | 免费 |
| 学员作答隐私 | 作答只在本机，不上传（见 06 文档 §11），因此**不产生计费事件** |

「学习内容消费免费，问答才计费」——这条边界同时写进产品口径与 UI（门户定价页、学员端余额 pill、额度中心）。

### 2. 额度账本（ledger-first）

| 项 | 规则 |
|---|---|
| 表 | `quota_ledger(id, user_id, delta, reason, ref_id, idempotency_key, created_at)` |
| 余额 | **余额 = SUM(delta)**，不单独存余额字段（避免双写不一致） |
| 扣减 | 必带 `idempotency_key`（如 `qa:<requestId>`），唯一索引防重放；重复请求返回同一结果，不重复扣 |
| 加赠 | 注册赠额、充值到账、运营补偿均为 `delta>0` 的账本行，带 `reason` 区分 |
| 明细 | 消耗明细**不含问题原文**（只记类型、时间、维度摘要，如「第 2 节 · 检索 3 片段」） |
| 审计 | 账本只追加不修改；冲正用反向行（`reason=reversal`），不 UPDATE 历史 |

### 3. 问答计费流程

```
学员提交提问
  → 云端校验令牌与课程可见性
  → 额度预检（余额 < 1 次 → 409 quota_exhausted + 充值入口；**检索与浏览不受影响**）
  → 混合检索（不计费）→ 平台模型生成 → 审核过滤
  → 成功：账本写入 delta=-1（幂等键）→ 返回答案 + 消耗明细
  → 失败（模型/审核/上游）：**不扣费**；若已扣则写冲正行
```

- 预检在检索之前，避免「额度耗尽时仍消耗平台算力」。
- 语音转写同样计一次（转写与问答合并为一次交互，扣一次额度，界面注明）。

### 4. 计费粒度

按次（起步简单、学员可预期）：一次问答 = 1 次，含转写；按 token 粒度后置（需求待冻结项）——需要时由账本 `reason` 扩展，余额口径不变。

### 5. 充值

| 项 | 规则 |
|---|---|
| 档位 | 点数包或订阅（定价与档位**待冻结**） |
| 渠道 | 微信 / 支付宝（**待冻结**） |
| 到账 | 支付成功**即时到账**（账本加行），幂等：重复回调不重复加额（按订单号唯一） |
| 状态机 | `created → paid → credited`（失败 `failed`/`expired`） |
| 退款/发票 | **后置**（需求待冻结项） |
| 合规 | 支付链路安全要求见需求非功能表；订单与账本分离（订单存渠道信息，账本只存额度变动） |

### 6. 额度中心（学员可见）

| 展示 | 要求 |
|---|---|
| 当前余额 | 常驻可见（插件侧栏余额 pill + 个人中心） |
| 本次消耗 | 问答完成即展示「本次消耗 1 次 · 余 N 次」 |
| 消耗明细 | 时间 / 类型 / 维度摘要（**不含问题原文**）、赠额记录 |
| 耗尽提示 | 明确「额度不足」+ 充值入口，**不静默失败** |
| 隐私 | 明细与日志不记问题原文；审计与用量账本分离 |

### 7. 运营侧与防滥用

| 风险 | 对策 |
|---|---|
| 重放扣减 | 幂等键唯一索引 |
| 并发超扣 | 扣减在单事务内完成（读余量 + 写行），余额不足即拒 |
| 赠额刷号 | 注册门槛 + 异常识别策略（需求待冻结） |
| 高频问答 | 按账号 / 设备限流（429） |
| 支付重复通知 | 订单号唯一 + 账本幂等键 |

- 运营可查：按用户/时间/类型的扣减流水与汇总；异常高频扣减可定位。
- 补偿/赠送：走账本加行（带 `reason` 与操作人），不走 UPDATE。
- 额度是**对外计价单位**，用量账本是**对内成本账**；两者通过 `reason/ref_id` 关联，不合并。

## 第二部分 · 模型配置与 AI 用量

### 8. 定位

平台承担全部推理成本：教师零密钥（生产）、学员零配置（问答）。模型配置因此是**平台运营面**的必备能力，也是成本与质量的控制点。

角色：**仅 operator/admin 可维护模型配置**；producer 与 student 无任何密钥入口。

### 9. 模型条目与任务级主备

| 项 | 规则 |
|---|---|
| 条目 | `ai_models(id, purpose, provider, model, api_key_enc, status, cooldown_until, meta)` |
| purpose | `llm`（文本生成）/ `vlm`（视觉理解）/ `asr`（转写）/ `embedding`（检索向量）/ `image`（文生图，仅装饰图） |
| 密钥 | AES-GCM 加密存储，master key 来自环境注入；**明文不进浏览器、不进日志、不进响应** |
| 状态 | `active` / `cooling`（连续失败冷却）/ `disabled`；冷却期不出现在路由候选 |
| 连通性测试 | 管理端手动触发（不消耗生产预算），结果落 `ai_runs` 供追溯 |
| 绑定 | `ai_task_bindings(task, primary_model_id, backup_model_id)`；任务键与 05 文档 §13 的命名空间一致 |
| 路由 | 主模型优先；失败且可重试（429/5xx/超时）→ 自动切备；备也失败 → 任务失败并按 05 规则回灌/待办 |
| 不可重试错误 | 参数非法、媒体非法、内容审核拒绝 → **不切备**，直接失败 |
| 绑定变更 | 运营可改；改动只影响新任务，进行中任务用原绑定（可追溯） |

### 9.1 provider 协议适配（实现级）

模型条目不止是"一个 key"，还要适配不同厂商的协议形状：

| 项 | 规则 |
|---|---|
| 协议字段 | `protocol=openai\|anthropic`（内容 LLM 两者均可；**embedding 只能 openai**）；ASR 独立配置 `protocol=minimax\|openai` |
| 默认条目 | 部分唯一索引保证每个用途最多一个 `is_default AND is_active` |
| openai 调用 | `{baseUrl}/chat/completions`，内容生成带 `response_format=json_object` |
| anthropic 调用 | `{baseUrl}/v1/messages`，带 `x-api-key` + `anthropic-version: 2023-06-01`；响应取 `content[].text` 拼接；`stop_reason=max_tokens` 视为**截断**（不可当完整答案入库） |
| embedding 维度 | **必须 1024 维**：请求显式带 `dimensions: 1024`；模型不支持该参数返回 4xx 时自动重试一次**不带** `dimensions`；最终仍按 1024 校验，不合规则拒绝该条目 |
| 连通性测试 | 与正式调用走**同一协议分支**，避免"测试通、实际不通" |
| 密钥密文 | `api_key_encrypted` 形如 `v1:<iv>:<tag>:<ciphertext>`（AES-256-GCM，base64url）；解密失败按**未配置**处理；DTO 只回 `apiKeyMasked`（前 4 + `*` + 后 4）或「无法解密，请重新录入」；明文永不落库/日志/响应 |
| 密钥更新语义 | `PATCH apiKey=""` **保留原密钥**（空串不是清空）；`baseUrl` 自动剥离常见端点后缀 |
| 生效时机 | 运行时按操作解析：**ingest 开始取 ASR、generate 开始取 content LLM、检索建索引取 embedding**；管理员保存后**下一次操作即生效，无需重启** |
| 缺失行为 | ASR/LLM 缺失 → 对应阶段 `503`，**不影响服务启动与其他接口**；embedding 缺失 → 允许发布但 `indexed=false`（仅词法召回） |
| 权限 | 模型配置接口仅 `admin`；operator 只读 |

### 10. 用量账本与预算

| 表 | 内容 |
|---|---|
| `ai_runs` | 一次调用一行：`source`（cloud / producer / student_qa）、`task_key`、`model`、`provider`、`tokens`、`latency_ms`、`status`、`summary?`（结构化摘要 ≤8KB，如评审评分与 verdict） |
| `ai_run_steps` | 一次调用内的分步（如逐节生产九步） |
| `ai_usage_events` | 可计量事件：`kind ∈ {tokens, images, asr}`、数量、关联 run |

- **不记录 prompt 与产物正文**，只记数字、模型标识与版本号。
- 生产与学员问答**同一账本、同一筛选界面**（source 区分），避免两套成本口径。
- 溯源上报接口：`POST /v1/admin/content/provenance`（05 文档 §13）。

| 预算项 | 规则 |
|---|---|
| 口径 | 组织预算按 `source` 分通道（生产 / 学员问答）分别计量 |
| 预警 | 达 80% 预警（管理台提示 + 通知） |
| 硬停 | 达 100% **停止新增调用**（在产任务不中断，显式提示） |
| 图示额度 | 每节/每课/单课/月度四层限额；超限 `409 image_budget_exceeded`，图标「待生成」，教材照常发布 |
| 预算是软熔断 | 任何情况下不得产出无账本的调用 |

### 11. 学员问答侧的模型使用（ADR-03）

| 项 | 规则 |
|---|---|
| 模型来源 | 平台预置，学员端不暴露模型选择（也不需要 BYOK） |
| 路由 | 问答任务按 `student_qa` 绑定模型；平台侧保证 P95 首 token ≤ 3s |
| 审核 | 生成内容**必须**经云端审核过滤（提示注入、违规内容、买卖建议）后出口 |
| 成本 | 计入平台成本；对外按额度计价（§1–3） |
| 降级 | 主模型故障时切备；两模型均不可用时明确提示「暂不可用」，不返回未审核内容 |

### 12. 安全与运营台面

- 密钥仅存加密列；解密只在调用时短时驻留内存，不落日志、不进错误信息、不进 trace；管理端只显示掩码（尾 4 位）与可用性。
- 任何模型配置变更落审计（操作人、时间、前后值掩码）；学员与教师**均无凭据托管面**。
- 运营台面（对齐原型 ops-models / ops-usage）：
  - **模型配置**：模型条目列表（状态/冷却/最后测试）+ 任务级主备绑定 + 行内测试/编辑/删除 + 渠道参数（ASR 热词注入术语表）。
  - **模型用量**：统计卡（总调用/总 token/成本）+ 按任务/按模型分布占比条 + 按来源（生产/学员）拆分 + 明细（sparkline）+ 预算 80%/100% 进度条。
  - **成本换算**：按模型单价配置估算（需求待冻结：单位成本 × 目标毛利）。
