# 02 生产端服务端化决策（ADR）

日期：2026-11-11　状态：已采纳（教师端需求 v0.2 起生效）

## 决策

**生产端（教师/课件制作）不再以 dsh 插件实现，改为云端直接实现**：教师在浏览器中使用生产工作台完成全部流程；生产编排（九步引擎）由云端 worker 执行；**模型由云端预置**（模型配置页维护，加密存储、任务级绑定），教师零本地安装、零密钥。

学员端（coach 插件）**维持 dsh 形态不变**——学员问答 + BYOK 是真对话场景，harness 用对了地方；dsh 平台基线此后仅约束学员端。

本决策**正式反转**前代口径「云端不内嵌生产 Agent 循环」。

## 动因

1. **复杂度大头来自 harness 而非业务**：装机链（Node → 精确版本 dsh → tgz → sha256 → 装机脚本 → 九项自检 → 凭据库权限 → 面板登录 → 贴密钥 → 12h 令牌重登 → 更新重装）全部是为插件形态付出的成本；而实际使用形态是「面板卡片 + 看板 + 三个决策点」——纯 Web UI 模式，不依赖对话式驱动。生产端是**任务型工作流**，对话 harness 是错配工具。
2. **旧原则早已名存实亡**：云端本就运行管线生成（教材 LLM、图示、转写、关键帧）等 LLM/VLM 编排；源视频直传云端、帧轨道在云端，「教员本机算力」不成立。生产循环是 IO-bound 的 API 编排，非本地推理。
3. **模型预置设施现成**：模型配置（AES-GCM 加密、任务级主备、健康冷却）、用量账本（`source='producer'` 通道）、组织预算硬停——教师从自备 Key 变为零密钥，成本集中可控。
4. **风险蒸发**：dsh rc 长任务稳定性风险（原备选 DeepAgents）整体消失；云端已有 DB 任务队列 + worker 心跳恢复先例。

## 已重定的相邻决策

| 项 | 结论 |
|---|---|
| 云端 worker | 生产编排入云端 worker 池；九步引擎、断点续跑（云 DB checkpoint）语义不变；新增逐节并行度上限 |
| 工艺包 | SKILL.md 热挂载（customSkillDirs）→ 服务端版本化工艺配置（格式待冻结） |
| 门禁①② | dsh 审批 UI → 工作台审批组件（扩展既有「签批终审」交互先例） |
| 追加素材三选一 | 工作台决策卡（影响面先算再问，语义不变） |
| 成本 | 教员自备 → 云端统一计费；VLM 理解用量需重估预算线（见需求 v0.2 待冻结） |
| monorepo | `apps/producer` 不再需要；生产编排成为云端内部模块 |
| 后置能力 | 对话式微调单节（当前三决策点用不上） |

## 代价

- 云端并发与规格需评估（原教员机水平扩展 → 集中式 worker）
- VLM/LLM 用量全部入云端账本，预算线需重定
- 一次性迁移成本（若自 trend-studio 存量迁移；trend-suite 为绿地项目，直接按新架构实现）

## 对流程的影响

教师旅程由七阶段（A1–A7）坍缩为四阶段（B1–B4）：**开账号 → 素材与骨架（门禁①）→ 逐节生产（评审/追加素材决策点）→ 交接发布**；A1 自备 Key、A2 装机、A7 运维三个阶段整体消失（运维归云端）。详见 [教师端需求 v0.2](../requirement/教师端需求v0.2.md) 与 [流程图](../flow/teacher-e2e.html)。
