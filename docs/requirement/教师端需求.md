# 教师端需求

> **一句话**：教师用浏览器把一段课程录像变成可发布的教材——九步生产由云端 Agent 承担，人只守住方案、评审和必要的微调。

- 读者：产品、云端开发

## 1. 谁在用，能做什么，不能做什么

**教师**（账号角色 `producer`）是课件制作人员：打开浏览器工作台就能做课，不装任何东西、不配任何密钥、不做运维。

| 边界 | 含义 |
|---|---|
| 只写草稿 | 教师的一切写入都是 `draft`；签批与发布是运营（operator/admin）的事 |
| 模型云端预置 | 生产用的模型（含 VLM 理解）由运营在模型配置页维护（加密存储、任务级主备绑定）；教师侧零密钥 |
| 结构不发明 | 课程目录以人工目录为先验骨架，Agent 只做校验与归一 |
| 零安装零配置 | 教师侧只有浏览器一个依赖；不上传密钥、不装插件、不连本地服务 |

**验收尺子**：新教师拿到账号，**打开浏览器即可制作第一节课**；全程只在三处被打断——方案审阅、评审驳回、追加素材处置。

## 4. 场景详述

### 4.1 准备

#### T1 首次登录进入工作台

**场景**：教师第一次拿到账号，要在最短时间内开始做课。

**前置**：管理员已建好 `producer` 账号；模型已由运营预置。

**操作**：用账号密码或一次性邀请码登录，打开生产工作台。

**系统行为**：
- 工作台是 `producer` 角色专属入口，学员账号不可见该入口
- 会话是 Web 会话，令牌仅存 `sessionStorage`，不落 Cookie
- 教师侧无需任何模型配置页面，也无需上传密钥
- 课程在课程列表页全程管理：新建、改名、删除都在列表页完成；删除课程会连同它的全部素材关联、方案、生产产物与 Agent 对话记录一并删除（二次确认，不可恢复）
- 课程卡整卡可点，入口文案固定为「进入课程」——不随阶段变化；点进即该课当前阶段的对话工作流页（方案未批准进方案页、已批准进制作台）；素材上传收口在素材库，课程内不再单设素材页

**预期结果**：
- 登录后直接进入工作台，看得到自己的课程列表与「新建课程」入口
- 课程卡显示这门课的状态、章·节数、进度与进展提示；入口按钮文案稳定不变，去哪个页面由系统按进度决定
- 全程零安装、零命令行、零配置项

#### T2 开通教师账号

**场景**：教研组新来一位老师，管理员要给他一个能登录的账号。

**前置**：管理员已登录运营控制台。

**操作**：在账号页新建 `producer` 账号，用密码（scrypt 哈希）或一次性邀请码（单次有效）交付。

**预期结果**：账号可登录；邀请码用过即失效；工作台只对 `producer` 开放。

#### T3 生产模型预置

**场景**：生产链路需要模型，运营要在教师开工前把模型配好。

**前置**：运营已登录运营控制台。

**操作**：在模型配置页维护模型条目（每条可选多个用途，如同一模型同时勾选内容生成与视觉理解，无需重复添加）；选择预置厂商（智谱、MiniMax、DeepSeek、Kimi、阿里通义、字节火山，支持自定义）自动填充该厂商该协议的端点地址，可修改；做任务级主备绑定与连通性测试。

**预期结果**：
- 密钥 AES-GCM 加密存储，**明文不进浏览器、不进日志、不进响应**
- 连通性测试与正式调用走同一协议分支（避免「测试通、实际不通」）
- 点击测试后条目行内显示「测试中…」；测试结果（延迟毫秒 / 失败原因）随条目落库并在列表内联展示，不只在一次性提示里
- 主模型失败且可重试（429/5xx/超时）时自动切备；参数非法、媒体非法、内容审核拒绝**不切备**

### 4.2 素材与方案

#### T4 把视频拖进课程

**场景**：教师手上有一段 30 分钟的课程录像，要让它成为课程的原始素材。

**前置**：已登录工作台；素材上传统一在「素材库」完成。

**操作**：把视频文件拖进素材库，上传时选好归属课程。

**系统行为**：
- 签发直传凭据（HMAC 绑定素材 + 字节数 + 摘要 + 有效期）
- 浏览器直接 PUT 字节到云端存储，**不经业务进程内存中转**
- 落库确认后入队转写；上传进度可见、可重试
- 素材归属上传时选定的那门课：归属不变，但**一份素材可以被多门课选用**（建课时勾选、起草时勾选）；一门课可上传多个素材，**默认全部参与规划**（起草时可勾选其中几份）；上传区说明视频属于哪门课
- 素材库是**跨课程的全局视角**：教师名下所有课程的素材收在一处，每份素材标出归属课程，可按课程筛选、按文件名搜索；素材上传与转写只收口在素材库，课程页不再单设素材入口
- 只能选自己名下课程的素材；别人的素材选不进自己的课

**预期结果**：
- 单文件 ≤ 2GiB
- 视频必须同时含视频流与音频流；缺音轨直接拒绝并清理半成品
- 中断后可重试，不产生重复素材
- 教师不需要猜「该传几个、传到哪」：素材库里选好归属课程即可

#### T4b 素材三段：逐字稿 / 关键帧 / 视频理解

**场景**：素材早就加工完了，但当时没有理解结果（理解阶段晚于素材上线），课程规划需要它的讲解要点；或者某一段转写质量不好，要单独重做而不必整条重来。

**前置**：素材已就绪（`ready`）。

**操作**：在素材卡上点某一段的「重新生成」或「删除结果」。

**系统行为**：
- 一份素材的分析固定拆成三段：**逐字稿**、**关键帧**、**视频理解**；三段各自有状态（未开始 / 进行中 / 已完成 / 未完成 / 失败）与产出条数，教师能一眼看出哪一段缺东西
- 每段各自可看结果、可重跑、可单独删除结果：删一段只删那一段的产物，素材字节与另外两段不受影响
- 重跑默认**只补缺口**（按块去重，不重复计费）；要清掉重来，先删该段结果再重跑
- 理解段要有逐字稿才能跑；没有逐字稿时拒绝并提示先重跑逐字稿
- 三段互不联动失效：补一段不会连带清掉另外两段
- 理解结果被课程方案引用时不可清空：拒绝并说明先处置引用，避免课程内容悬空
- 同一素材同时只有一个加工任务在跑；已有任务在跑或排队时触发单段重跑被拒，提示先停止

**预期结果**：缺哪段补哪段，其余产出保留；不重复计费、不重复加工。

#### T5 边传边看转写

**场景**：老师不想等整段转写结束才开工。

**前置**：视频已上传，转写进行中。

**系统行为**：每转完一块即落可读段落（`partial` 标记）；理解与生产提前起跑；关键帧轨道先于转写完成。

**预期结果**：转写进行中就能在页面上读到已转写段落，并标明是未完成内容。

#### T19 停止加工

**场景**：文件传错了或这段素材不再需要转写，教师要停掉正在跑的加工，不让它白跑。

**前置**：素材已上传，加工任务排队中或运行中。

**操作**：在素材卡上点「停止加工」。

**系统行为**：
- 排队中的任务直接取消；运行中的任务在当前阶段边界安全中止，不产生半块脏数据
- 素材回到「已上传」态；已转出的段落与关键帧保留，重新触发加工时按块去重续转，不重复计费
- 没有进行中任务的素材点停止被拒并说明原因
- 单段重跑与整条加工互斥：同一素材同时只有一个任务在跑

**预期结果**：停止后不再产生新的转写与计费；素材保留，可重新触发加工或直接删除。

#### T20 删除素材

**场景**：素材传错或确认不再需要，教师要把素材从课程里彻底移除。

**前置**：素材已在库中。

**操作**：在素材卡上点「删除」，确认后执行。

**系统行为**：
- 素材行、转写段落、关键帧与已落盘字节一并删除，不残留半成品
- 正在加工的素材删除前先自动停止其加工任务
- 已产出理解成果（source units）的素材不可直接删除，明确提示需要先处置方案引用（走 T9），避免课程内容悬空
- 删除只影响素材本身，不动已有课程方案与章节

**预期结果**：删除后素材列表不再出现该条目；重传同名同大小文件作为新素材入库，不复用已删条目。

**只删某一段结果**：教师只想重做一段时，删该段结果即可——素材字节与另外两段保留，素材仍在库里。

#### T6 课程骨架与概念归一

**场景**：一门课要覆盖哪些章节、术语怎么统一，得先定下来。

**前置**：素材已入库；教师提交了课程目标（人工目录可留空，由 Agent 代拟）。

**系统行为**：
- **目录先验**：以人工目录为骨架，目录外的内容不创建章节
- **目录先验可在建课时随课程一并提交**，也可在起草时补交；两种来源同源，落库后原文与目录树一一对应
- 建课时提交的目录认不出层级的行**不拦建课**——原文照存，目录树不落，教师可在方案页改格式重提
- **目录先验贯穿到课时层**：课时标题取教师原文，模型改名不改骨架
- **目录可代拟**：教师只给课程目标时，Agent 依据目标与素材代拟一版目录先验并回写，之后以该版为准
- **目录编号口径**：三级编号（篇 / 章 / 课时）——篇与章用中文数字，**章号全书连续**（第二篇的第一个章接在第一篇的最后一个章之后，不重新从「第一章」数起），课时号在章内重排。Agent 代拟与教师端一键规整同一口径；教师原文里已有的编号沿用不改。
- **概念归一**：术语进概念表，含别名与依赖边；重复名、自环直接拒绝
- 目录是骨架的下界：起草没提到的目录章节仍然保留，只是标为「证据不足」交教师裁决
- 越界内容有明确拒绝理由（目录外章节、重名概念、未收录依赖边、成环依赖），不静默丢弃

**预期结果**：产出一份可信的骨架与概念图谱；越界内容有明确拒绝理由而不是被静默吞掉。

#### T7 触发制作方案

**场景**：素材齐了，教师要让 Agent 起草课程方案。

**前置**：素材就绪度为 `ready`（或教师明确允许 `partial`）。

**操作**：在方案页中栏对话区把课程目标发给 Agent（自由文本，目录先验可整段粘贴），规划方式等结构化选择由 Agent 以确认卡提问、教师点选即答；**首次打开课程（还没有方案）时，对话区空态提供「选择素材，开始制作」入口**——弹窗以视频方格墙呈现素材库视频（关键帧封面 + 时长角标 + 悬停视频预览，可跨课选用，没跑理解的整卡置灰并标注「需重跑理解」），确认制作即把所选素材发进对话流，Agent 依此触发起草；教师在对话里明确只用部分素材时同样生效（目标可留空由 Agent 代拟，缺失时 Agent 向教师要）。

**系统行为**：
- 触发时预检所选素材就绪度
- **方案由教师显式触发**，Agent 不从上传行为推断课程边界
- 素材未全部就绪时触发被拒并说明原因，教师补齐后可再触发
- **建课即可起草**：新建课程时填课程目标、勾选参与本次规划的素材（含其他课的素材）、可选粘贴目录先验，一键「创建课程并生成大纲」；起草没启动时课程仍然建成，原因带到方案页显示，不让教师为同一个错误再建一门课
- **没跑理解的素材不能选**：建课与起草时置灰并标注「需重跑理解」——没有教学要点可比，选了也规划不出东西
- 起草是后台任务，工作台轮询任务状态，草案四件套产出后自动呈现
- **可勾选参与本次规划的素材**：不勾选即课程全部素材；勾选后只对所选素材做总体规划，多份素材的规划结果合并为一份目录
- **规划方式二选一**：「智能重新规划目录」（Agent 依据素材讲解要点重排三级目录）或「沿用人工目录骨架」（教师粘贴的目录为下界，Agent 只在其上做证据匹配与分节）
- **智能规划以素材的讲解要点为输入**，不把转写原文整段塞进 Agent：每个课时必须绑定出处（证据单元），出处同时决定目录卡片的「来源」与素材覆盖率
- **沿用人工目录同样把素材讲解要点清单交给 Agent**——没有要点清单，模型无从引用出处，匹配度只能靠猜
- **课时以目录为准**：目录里的每个课时级节点就是一条课时，**标题取教师原文**；模型改名、改结构都不改骨架，模型只提供出处、粒度与并行槽位；挂不上的模型课时剔除并留痕
- **匹配度一律由出处推导**，两种规划方式同口径；模型自评的匹配度只在没有出处可依时兜底
- **课时估时按绑定出处的真实跨度**（素材里这一段有多长），没有出处时取模型估值——不设分钟数地板
- **目录规模由素材推导**，不按固定上限铺开：一课时 = 一个可独立讲清的知识点；一课时至少覆盖 8 分钟素材、至少 1 个知识点要点；规模区间在起草时给定，Agent 超出的部分被裁掉并留拒绝记录
- **智能规划的前提是素材已有理解结果**：所选素材没有讲解要点时触发被拒，并指向素材页的「重跑理解」入口
- **规划自检**：智能规划的产出逐条自检（出处是否齐且在素材清单内、课时数是否落在素材推导的规模区间内、层级是否断链、有无空章空篇、课时标题是否重复或是空话、课时是否挂到目录节点上、分节课时数与目录课时数是否一致）；**自检不通过的方案不呈现给教师**
- **自检不通过自动重规划**：失败项回喂 Agent 重规划，**最多 3 次**；连续 3 次不通过转人工待办，方案不落库、不呈现
- 起草失败要说清是谁的问题：上游模型配额用尽 → 提示联系运营（改目标或目录无用）；参数或内容问题 → 指向改目标或目录重提；上游临时故障 → 提示稍后重试
- **草案完成在对话流中汇报**：起草仍是后台任务；四件套产出后综合 Agent 在方案页对话流中汇报结果，并就「是否批准」发起确认卡（见 T8）；教师用对话自由文本或快捷指令触发重新梳理
- **右栏是纯工作区**：方案页右栏只呈现产物（大纲 / 术语 / 分节 / 轨迹）与微调入口；对话区内只有三种交互（自由文本、AskQuestion 确认卡、一点即发的快捷指令），所有工作交互只在中栏对话区，右栏引导横幅只做状态呈现或定位到对话区

**预期结果**：产出骨架 + 概念图谱 + 术语表 + 分节计划草案，进入 T8 审阅；目录规模与素材规模匹配，每个课时可回溯到出处。

#### T8 审阅方案：批准 / 微调 / 打回

**场景**：方案是整门课的骨架，教师要在开工前把住这一关。

**前置**：方案草案已生成，尚未解锁逐节生产。

**操作**：在方案页与综合 Agent 对话（批准 / 打回 / 问依据都在对话里进行），或在右栏产物区直接微调大纲。

**系统行为**：
- **方案页统一中置对话布局**：中间是与综合 Agent 的**真多轮对话流**——起草、打回、解释依据、裁决都在对话里；右栏是一整个**页签工作区**（类似工作台素材库的呈现方式）：头部页签切换产物（大纲 / 术语 / 分节 / 参数 / 版本轨迹），点页签看对应产物，在页签里直接微调，**工作区宽度可拖拽调整**。页面上不再出现两个「跟 Agent 说话的地方」，也不再出现「上传与转写 / 制作方案」这类阶段页签
- **右栏微调即时生效、不进对话**：右栏的改名 / 挪位 / 删节 / 加课时 / 改别名直接落库（受下文微调约束），不写对话消息、不触发模型调用；版本轨迹记录每处调整的来源（Agent 起草 / 对话裁决 / 右栏直改）
- **批准走对话内确认卡**：Agent 以确认卡（问题 + 选项 + 说明）发起批准确认，点选即回答并回显；**「批准」是确定性动作，由服务端按所选选项直接执行、不经模型**——批准前的全部门禁校验原样保留
- **待裁决事项在对话里问**：匹配度不足、证据不足等需要教师裁决的事项由 Agent 以确认卡提出（如 补素材 / 移除该章 / 保留并标注），选择即执行对应的确定性动作
- **批准**：方案锁定为基准版，解锁逐节生产
- **微调**：结构化编辑方案条目（章节增删合并 / 改名 / **移动** / 概念别名 / 分节粒度 / **课时顺序**），即时生效
- **移动的层级约束**：篇只能放顶级、章只能挂篇、课时只能挂章；不能把章节移进它自己的下级；不能把一个父节点搬空（空章会变成没有课时的生产节）——违反即拒绝并说明原因
- **打回**：给一句自然语言修改指令，综合 Agent 基于**已有 source units** 重起草——不重跑素材理解，秒级返回新草案
- **版本历史**：草案与人工修改留版本轨迹（v1 → v2 …）；确认后锁定，中途变更只能走 T9 的「重做骨架」
- **方案里看得见出处**：骨架节点与课时都带出处明细（出自哪份素材的哪几分钟、讲了哪些要点），教师能逐条核对
- **大纲只有一棵树**：篇 / 章 / 课时三层，篇与章可折叠；课行带匹配度、时长与出处 chip；改名 / 挪位 / 删节 / 加课时都在这棵树上做，即时生效
- **微调后重算匹配度**：匹配度由出处推导，删节、挪位改了节点的归属就必须跟着重算；空掉的章判为证据不足，交教师裁决
- **拒绝记录分两类**：已自动处理的（剔除目录外课时、剔除清单外出处、裁掉超规模课时等）只留痕，不阻塞批准；待教师裁决的才阻塞
- 存在「证据不足」分节或待教师裁决的拒绝记录时，批准被拒，并由 Agent 以确认卡告知要裁决哪些项——裁决在对话确认卡里完成
- 概念与依赖边在批准时才入库；重名术语被拒（409），别名撞上别的术语名同样被拒

**预期结果**：只有批准才解锁生产；微调与打回都不丢已有理解成果。

#### T9 追加素材：课程做到一半又拖进一段视频

**场景**：课程做到第三章，发现缺一段素材，得决定怎么并进来。

**前置**：已有课程正在生产或已生产部分章节。

**操作**：拖入新素材，工作台先展示影响面（哪些节会被重评），再选择处置方式。

**系统行为**：
- 先只读展示影响面，教师确认后才执行
- 三种处置：**A 只补这节** / **B 重做课程骨架** / **C 只入库暂不生产**
- 决策持久化；受影响节的**生产步骤重置**，但**回灌预算保留**

**预期结果**：教师在看到影响范围后再决定；决策有记录，重复触发不重复重置。

### 4.3 逐节生产（约占全程 90% 的时间）

#### T10 逐节自动生产

**场景**：方案已批准，教师希望剩下的事尽量不用管。

**前置**：方案已批准，逐节生产已解锁。

**系统行为**——生产由云端 Agent 链承载，工具调用与确定性校验都落云端：

| 角色 | 职责 |
|---|---|
| 理解 Agent | 多模态逐 chunk 处理素材（转写分组 + 采样帧），产出 source units；随素材就绪自动运行 |
| 综合 Agent | 目录先验校验、概念归一、起草制作方案（含分节计划）；支持打回重起草（复用 units） |
| 逐节子代理 ×N | 每节一个并行子代理，按**九步固定顺序**生产：案例股 → 行情同步 → 行情读回 → 图示 → 回放课件 → 正文 → 其余课件 → 评审 → 溯源；**引擎强制顺序**（跑错序被挡并提示当前步）；断点续跑（云 DB 即 checkpoint，worker 崩溃恢复不依赖本地状态）；并行度有上限 |
| 评审 Agent | rubric 十维自评（grounded 含「行情数值可核」一票否决），生成逐段修改指令 |

同一批产物还要满足：
- **教材正文**：Markdown 扩展 DSL + `[[unit:]]` / `[[stock:]]` 锚；事实段落必须可回溯 source unit
- **图示三路**：diagram（生成）/ keyframe（讲师关键帧）/ generated（文生图，仅装饰）——有配额，且**不得承载教学信息**
- **课件**：11 类组件白名单 + 断言词表 + 确定性生成器（详见 [教材呈现与交互课件 §7–9](../arch/06教材呈现与交互课件实现方案.md)）
- **案例股与行情口径**：腾讯前复权、周期原生日 K / 周 K、均线位白名单、复权漂移声明（详见 [教材呈现与交互课件 §5](../arch/06教材呈现与交互课件实现方案.md)）

**三层校验**：schema → 语义（断言证明 / 术语 / 引用 / 媒体锚点）→ 教学质量（rubric 评分，grounded 含「行情数值可核」一票否决）。失败即回灌重写，**≤ 3 次**；超限进 T14 人工待办，**绝不部分落库**。

**预期结果**：一节内容要么完整通过三层校验进入草稿，要么显式挂起或进待办，不存在「半成品入库」。

#### T11 在看板上盯进度

**场景**：教师想随时知道整门课到了哪一步。

**系统行为**：生产看板是工作台主视图——每节一行九步状态 + 产出计数 + 最近评审结论 + 追加素材决策 + 人工待办入口；「当前步」口径与引擎一致；每步附目标、用的工具、常见坑。
- **制作台进度与看板同源**：制作台以对话流为主轴——九步进度由生产引擎写 **Agent TODO 卡**进对话流（始终呈现最新清单），步骤起止 / 模型调用 / 失败原因以事件消息呈现；看板与 TODO 卡从同一状态推导，不出现两套口径。

**预期结果**：看板显示的当前步与引擎实际所在步骤一致，不出现两套口径。

#### T21 看着 Agent 做，并能随时停下来改

**场景**：制作要跑很久。教师想在旁边看着它做，做到某一步发现内容不对，想让它先停下来——改完再继续，而不是干等一整轮跑完。

**前置**：课程方案已批准，生产已起跑。

**操作**：在制作台对话流看 Agent 的制作过程；停止 / 继续是对话动作——在对话里说，或点对话输入区的快捷指令（两者等价，走同一确定性端点）。

**系统行为**：
- **制作过程按步留痕**：每步的开始与完成、每次模型调用（模型、耗时、token）都进对话事件流（agent 消息），前端带游标增量续读
- **历史制作可回看**：对话流出现之前生产的课程，其旧版事件按原顺序回填为对话事件——教师在制作台能看到这门课当时是怎么被做出来的，回填不混入新对话（只搬还没有任何消息的线程）
- **顶部面包屑定位**：面包屑在对话流顶部第一行，显示当前制作的课件位置（课程 / 章 / 课时）；右栏是页签工作区（课件 / 出处 / 课时），**工作区顶部显示制作完成进度**（节数 · 步数 · 百分比与进度条）；右栏顶部不放任何按钮，不放状态横幅与运行条；不再出现「课程大纲 → 课件制作 → 成品审阅 → 交付运营」流程条
- 事件流**只记事实**，不复述模型措辞——模型写了什么在教材正文里，事件流只回答「做到哪一步、花了多少」
- **停止后由确认卡接续**：停止落定后 Agent 在对话流落事件消息，并以确认卡询问如何继续（改完继续 / 先改大纲 / 放弃本节重做），选择即执行对应的确定性动作
- **停止是步边界安全中止**：当前步跑完才停，步内产物不丢，不产生半截入库
- 已完成的步成果保留；回灌预算（重试次数）不清零
- **停止点可见**：停在哪一节、哪一步，教师一眼看到
- 继续制作从停下的地方续跑，已完成的步不重跑
- **停止后立即继续**：worker 还没走到步边界时继续，撤销停止请求、同一轮接着跑——不新建任务，已完成的步与回灌预算都不动
- 没有可停的制作任务时点停止被拒并说明原因；制作确实在跑时点继续被拒并说明原因

**预期结果**：教师随时知道做到哪一步、花了多少；停下来改完能继续，已完成的步不白做。

#### T12 评审与返工

**场景**：一节做完了，但质量不够，要打回重做。

**前置**：某节通过校验，进入主编评审。

**操作**：在工作台评审卡看十维评分与逐段修改指令，给出 approve / reject。

**系统行为**：reject → 回灌重写（带修改指令，≤ 3 次）；每次回灌带回具体失败原因。

**预期结果**：approve 的节进入草稿；reject 的节带着明确的修改指令重跑，不是从零重做。

#### T13 把教材编排成课堂

**场景**：教材写好了，但学员要的是「有人讲」的课。教师要把这一节变成可播放的课堂：讲解稿、白板脚本、引导点、随堂测验。

**前置**：该节的教材与互动课件已通过三层校验。

**操作**：在工作台进入「课堂编排」，为本节生成或调整课堂内容。

**系统行为**：
- **场景骨架**：一节课编排为若干场景序列，四类——讲解页 / 随堂测验 / 交互课件 / 项目制练习
- **讲解稿**：逐段讲解文本（含元素引用与讲解顺序），教学要点必须来自教材正文与已通过的 source unit
- **白板脚本**：逐笔绘制动作（文字 / 图形 / 图表 / 公式 / 表格 / 代码），与讲解稿逐句对齐
- **引导点**：标注高亮、激光笔、组件引导的落点，课堂运行时按脚本触发
- **随堂测验**：单选 / 多选 / 简答题与判分反馈（答案唯一、解析可回溯 source unit）
- **人设**：AI 同学与辩论角色的人设（身份、声音、性格），角色数与音色可配
- **一致性**：课堂内容与教材同源——正文改动即课堂失效（内容指纹覆盖课堂），杜绝教材与课堂讲的不一致

**预期结果**：
- 课堂内容与教材一起进草稿、一起进发布就绪度判定
- 课堂不引入教材里没有的结论（grounded 纪律对课堂同样生效）
- 讲解音轨不由云端预生成——课堂只存讲解文本与脚本，音轨在客户端本地合成

> **对标**：场景类型与动作词表参考 [OpenMAIC](https://github.com/THU-MAIC/OpenMAIC)（MIT）的课堂契约；差异是本项目的课堂**发布前编排好**、音轨本地合成，不即时生成。

#### T14 人工待办

**场景**：有些问题 Agent 判不了，必须人来裁决。

**系统行为**：回灌超限（≤3 次未收敛）、概念归一冲突等显式待办进入工作台待办区。

**预期结果**：待办可见、可处理，**绝不静默丢弃**。

### 4.4 交接、发布与轻量编辑

#### T15 看发布就绪度

**场景**：教材做完了，教师想知道能不能发。

**系统行为**：
- **内容完整性拦在编辑保存时**：轻量编辑与工作台直改保存时跑轻校验——图示引用可解析、课件断言有证明、片段窗合法，复用生产期同一批校验函数；断链内容存不进去，不攒到发布时才暴露。
- **发布前完整性终检**：发布动作前置跑一次同源终检兜底（覆盖绕过工作台的改动路径）。
- **签批状态**：未签批 / 已签批 / 待重签（`approval_stale`）三态可见，附内容指纹与待办数。
- 就绪度不设独立卡片页：课程卡状态标、制作台页签标与签批状态承载，对话内可问。

**预期结果**：**检查一份实现**——保存校验与发布终检共用同一批检查函数，两边结论不会打架；标注与回放检查随 DSL v2 启用一并加入。

#### T16 结构化编辑

**场景**：某些元数据要精确改，不能靠 Agent 重写。

**系统行为**：三个编辑入口——节元数据 / 案例股清单 / 术语（归档可逆）；写恒为 draft。

**预期结果**：改动可逆、可追溯；正文与课件的**表现层**修改走 T17，DSL 结构与事实段不在这里手改。

#### T17 教材轻量编辑

**场景**：Agent 写出来的教材，教师想直接改几个字、换张图、调一下 K 线，不必绕到对话里描述一遍。

**前置**：该节教材已生成并渲染。

**操作**：在渲染后的教材里选中元素直接改。

**系统行为**：
- **文本**：点击正文段落 / 标题进入选中态，浮动工具条提供加粗、斜体、下划线、颜色、字号、对齐、清除格式；支持撤销 / 重做；检查器显示该段来源 unit 与「改动将触发轻校验」提示
- **图片**：点击图片进入选中态，可删除或替换。替换有三种来源——**素材库**（浏览本课程素材）/ **库内搜索**（关键字、类型）/ **本地上传**（直传凭据，同 T4）；替换留痕新旧素材 ID，可回退原图
- **K 线属性**：点击回放图打开属性检查器——股票代码、周期（日线 / 周线）、起始时间、数据状态（已采集 / 部分 / 未采集）。未采集时提供「去采集」并入队行情同步；改代码或周期后重新读回行情并重校验；读回失败时该图降级为占位并显式提示，**不伪造数据**

**校验边界**：轻量编辑只允许「表现层 + 措辞」。**不得新增或删除事实段、不得移除 `[[unit:]]` 锚**。保存时自动跑轻校验（锚点仍在 + 行情数值未变则通过）；触及事实锚或数值的修改被拒绝并提示「结构性改动走生产回灌」。

**预期结果**：改完即时生效、仍是草稿；**结构性改动**（事实段增删、`[[unit:]]` 锚变动、课件断言变化、行情数值变化、节增删）使已签批课程转 `approval_stale`（见 T15）——措辞润色、样式、图片替换不失效，留痕可回退。

#### T18 签批与发布

**场景**：课做好了，要发出去。

**系统行为**：签批与发布按钮**对教师隐藏**；发布由运营执行。签批 = 对课程**内容指纹**签名；发布 = 重算指纹比对通过后课程状态 `draft → published`，内容对学员账号可读（学员端读 API 就绪，学员端界面另立项）。发布迁移先行、失败可回滚。

**预期结果**：教师调到签批 / 发布端点返回 `403`；工作台不出现签批与发布入口；结构性改动使已签批失效转待重签（口径见 T17 预期结果）。

### 4.5 异常与人工介入契约

| 异常 | 怎么触发 | 系统怎么处置 | 教师做什么 | 预期结果 |
|---|---|---|---|---|
| 提纲与素材不匹配 | 综合校验发现某节证据不足（匹配度低于阈值） | 该节标红并给出匹配度 | 二选一：**修订提纲**（编辑后重跑综合）或**补充素材**（上传后重跑） | 其余节不受影响 |
| 课件证据不足 | 逐节生产中素材证据不足以支撑该节内容 | 子代理**挂起**该节（状态显式、进度保留） | 补素材 | 补充素材入库后**自动恢复**，不重跑已完成步骤 |
| 校验 / 自评失败 | 三层校验或评审 Agent 不通过 | 回灌重写 ≤3 次，每次带回具体失败原因 | 超限后按待办处理 | 不产生部分落库 |
| 概念归一冲突 | 术语归一时出现无法自动裁决的冲突 | 转人工待办 | 裁决后继续 | 不静默跳过 |

**共同纪律**：异常状态在看板可见；恢复动作幂等（重复触发不重复重置）；一切异常处理都不产生部分落库。

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 并发与规格 | 生产 worker 池：逐节并行度上限可配；队列深度与 worker 健康可观测；单课生产不阻塞其他课 |
| 成本 | 生产用量（LLM/VLM）全部入云端用量账本（`source='producer'`）；按任务/模型/课程维度可查；组织预算 80% 预警、100% 硬停新增生产（在产任务不中断，显式提示） |
| Agent 对话 | 方案页与制作台的 Agent 对话为真多轮会话；**确认类动作（批准、裁决执行）不经模型**——由服务端按用户所选选项确定性执行，模型侧无对应工具；对话轮次的模型用量入账本（任务维度 `agent_chat.*`） |
| 安全 | 教师仅持 Web 会话（sessionStorage，不落 Cookie）；无凭据托管面；云端文本按不可信数据处理（防提示注入）；密钥仅模型配置页加密维护 |
| 稳定性 | 长任务可中断恢复（队列 + 心跳）；校验失败不静默；回灌与待办显式；worker 卡死自愈——长时间无一次成功的数据库往返即判定停滞并退出进程，由容器重启策略拉起重新认领，排队任务不被吞 |
| 可观测 | 每个落库产物上报溯源（任务/模型/token/耗时/工艺版本）；不记密钥与产物正文 |

| T21 | 制作台进度与历史 | 右栏工作区顶部显示制作完成进度（节数 · 步数 · 百分比与进度条）；对话流出现之前生产的课程可见按原顺序回填的旧制作事件，不混入新对话 |
| T4 | 浏览器拖入 2GiB 内视频 | 进度可见；字节直达存储（不经业务进程内存中转）；中断可重试；无音轨拒绝并清理 |

| T4b | 逐字稿 / 关键帧 / 视频理解三段 | 各段独立显示状态与产出条数；重跑只补缺口；删一段不动素材字节与另外两段；理解被方案引用时拒绝并说明先处置引用 |
| T5 | 转写进行中 | 工作台可读已转写段落（`partial=true`）；理解提前起跑 |
| T6 | 目录先验与概念归一 | 目录外章节不被创建；概念重名 409 |

| T7 | 多素材智能规划 | 勾选多份素材做总体目录规划；课时数与素材规模匹配；每个课时可回溯出处；无理解结果时明确拒绝并指向「重跑理解」；自检不通过的方案不呈现，自动重规划 ≤3 次后转人工 |

| T8 | 方案审批组件 | 批准后逐节解锁；微调即时生效（含章节移动与课时重排）；打回秒级返回新草案且不重跑素材理解；骨架节点与课时看得见出处（素材名 + 时间码 + 要点） |
| T8 | 大纲单树 | 页面只有一棵树：篇 / 章 / 课时三层可折叠；课行带匹配度、时长与出处 chip；改名 / 挪位 / 删节 / 加课时即时生效并重算匹配度 |

| T21 | 停止与继续 | 停止是对话动作（对话输入或快捷指令）；步边界安全中止；停止后确认卡可继续方式（改完继续 / 先改大纲 / 放弃重做）；已完成的步与回灌预算保留 |
| T10 | 九步跑错序 | 引擎报错并指出当前该做第几步 |
| T10 | 单章全量 | 节教材+图示+课件全量通过三层校验入 draft；回灌 ≤3；绝不部分落库 |
| T12 | reject | 工作台评审卡展示修改指令；回灌后复审 |
| T13 | 课堂编排 | 讲解稿 / 白板脚本 / 引导点 / 随堂测验齐备且与教材同源；正文改动后课堂同步失效 |
| T9 | 追加素材选 A/B/C | 影响面先只读展示；决策入库；受影响节步骤重置而回灌预算保留 |

## 7. 边界与不做的事

- 教师端只有浏览器一个依赖：不提供本地安装、不提供密钥配置、不提供运维入口。
- 教师不签批、不发布、不做索引重建。
- 事实段与 DSL 结构不在工作台手改——改这些走生产回灌（见 T17 的校验边界）。
- 图示不承载教学信息；教学信息只由正文、课件与断言承担。
