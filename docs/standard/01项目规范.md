# 01 项目规范

## 1. 分支与提交
- 分支：main 为主干；功能 `feat/xxx`，修复 `fix/xxx`
- 提交：Conventional Commits，分批小提交，提交前检查敏感信息

## 2. 代码纪律
- 注释只写「为什么」；不写多段注释
- `apps/*` 之间禁止互相 import；跨端共享契约一律落 packages/contracts
- 应用内只一层 `src/`（Next.js 的 `app/` `public/` 等约定目录按框架惯例落位，业务逻辑仍只进 `src/`）

## 3. 测试
- 行为基线：`pnpm test` 全绿是合并前提

## 4. 数据与密钥
- 运行期数据一律落各应用 `workspace/`（gitignore），不提交入库
- 密钥只走 `.env` 注入；数据库变更走 `apps/cloud/db/migrations/`（幂等可回放）

## 5. 文档同步
- 契约/边界变化必须回写 docs/ 对应文档并更新 docs/README.md
- 需求文档只写系统行为：不写状态行、版本历史、决策记录与版本差异；演进轨迹看 git 历史
